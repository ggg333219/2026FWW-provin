# S3 大纲 AI 超时与本地回退状态

Status: ready-for-agent
Triage: ready-for-agent

## Problem Statement

教师在 S3 点击生成大纲后，模型请求超时会使 AI Engine 使用本地规则生成兜底大纲。当前教师可能把兜底结果误认为模型生成成功；Go 后端等待时间增加也不能消除 AI Engine 自己的较短超时。模型即使返回空节点而触发兜底，当前实现还可能将结果标记为未回退，造成状态不准确。

## Solution

让 S3 大纲生成有明确且一致的请求时限，并完整呈现生成来源状态。模型在预算内成功时正常返回 AI 大纲；调用超时、调用失败或模型结果无有效节点时，系统仍可生成可编辑的本地兜底大纲，但必须将其识别为兜底结果，并在教师端明确提示及说明可采取的后续操作。

## User Stories

1. As a 教师, I want S3 大纲生成在模型正常响应较慢时继续等待合理时长, so that 请求不会过早退化成本地兜底大纲。
2. As a 教师, I want AI Engine 的大纲请求时限短于 Go 后端请求时限, so that AI Engine 能返回明确结果而不会被 Go 先行取消。
3. As a 教师, I want 浏览器请求时限长于 Go 后端请求时限, so that 前端不会在后端仍等待模型时提前中止生成。
4. As a 教师, I want 模型调用成功时看到正常的大纲生成结果, so that 我能继续检查和编辑教学结构。
5. As a 教师, I want 模型调用超时或失败时仍获得可编辑的兜底大纲, so that 单次模型故障不会丢失工作流入口。
6. As a 教师, I want 兜底大纲被明确标记为本地回退结果, so that 我不会误以为它是模型生成的内容。
7. As a 教师, I want 模型返回空节点或无效结构时也看到回退状态, so that 所有兜底路径的状态都准确一致。
8. As a 教师, I want 看到面向用户且不泄露密钥或内部堆栈的回退原因, so that 我能判断是否需要重试或手工调整。
9. As a 教师, I want AI 成功结果与回退结果使用一致的大纲数据结构, so that 编辑、保存、确认流程不因结果来源而改变。
10. As a 教师, I want 回退提示与当前草稿及大纲内容同时保留, so that 查看提示时不会丢失已生成或手工编辑的内容。
11. As a 教师, I want 能在结果状态中区分 AI 成功、使用兜底和请求失败, so that 后续操作基于真实生成状态。
12. As a 开发者, I want 回退状态在 AI Engine、Go API 和前端之间保持一致, so that 日志、接口和用户界面不会对生成来源产生矛盾判断。
13. As a 开发者, I want 超时和回退测试不依赖真实 StepFun 网络或凭据, so that 回归验证稳定、快速且可在本地运行。

## Implementation Decisions

- 保持现有 S3 大纲生成端点和请求字段兼容；只扩展响应状态字段，不破坏既有调用方。
- 大纲专用模型请求预算目标为 90 秒，最多进行一次模型请求尝试。请求级联时限保持 AI Engine 最高 90 秒、Go 大纲生成/修订调用 120 秒、教师端 150 秒的顺序，确保内层服务先返回结果。
- 90 秒是大纲请求超时的上限；若运维通过现有 LLM 超时配置明确设置更低预算，则尊重较低值。普通 Go AI 请求与其他 AI Engine LLM 调用继续沿用各自现有超时和重试行为。
- AI Engine 大纲超时预算使用现有统一 LLM 超时配置作为上限来源，并设置 90 秒专用上限；大纲专用 LLM 客户端在任一格式调用失败、异常或响应无法解析时立即结束格式降级链，避免多个长调用累计超过 Go 等待预算，并由上层进入确定性本地兜底。关闭隐藏 SDK 重试和格式降级仅适用于大纲专用 LLM 客户端，不改变其他 LLM 调用。
- 超时、模型错误、不可解析结果和空节点均可走现有本地兜底逻辑；任何实际采用兜底节点的返回都必须设置 `used_fallback=true`。
- 生成结果需要携带可供调用方处理的回退原因类别。前端只显示安全、可理解的原因，不展示 API Key、原始请求头、完整异常堆栈或其他敏感配置。
- Go 创建大纲响应必须保留 AI Engine 的回退标记和安全原因；该状态随当前大纲结果提供给教师端，不依赖进程内临时日志推断。120 秒专用等待只应用于大纲创建和修订；其他 Go→AI Engine 调用继续使用共享客户端的现有超时配置。
- 回退状态描述大纲版本链的初始来源；手动保存和局部 AI 修订产生新版本时沿用该来源标记，提示应说明“大纲最初由本地兜底生成”，不得暗示后续修改未发生。
- 教师端对 AI 成功和回退结果使用相同的大纲编辑数据结构；回退状态以醒目的非阻断提示呈现，提示内容不得被描述为模型成功生成。
- 本规格不要求删除本地兜底；兜底仍可用于保持工作流可用，但其来源必须透明。

## Testing Decisions

- 测试以外部可观察行为为准，不断言私有辅助函数或具体内部实现。
- AI Engine API seam 使用确定性 LLM stub 覆盖：有效模型响应、超时异常、其他调用异常、空节点响应。分别断言节点结果结构、`used_fallback` 和回退原因类别。
- Go 创建大纲 API seam 使用 fake AI client 覆盖 AI 成功与回退响应，断言响应中的回退状态和原因与 AI Engine 契约一致传递。
- 前端/API 测试断言成功态不显示回退提示；回退态显示明确提示，且大纲内容仍可编辑、保存和继续现有流程。
- 超时配置测试断言 AI Engine、Go 和浏览器请求预算保持严格递增，并且 AI Engine 的单次调用预算不超过约 90 秒。
- 既有 prior art 包括 AI Engine 大纲构建/超时相关测试、Go 大纲服务和 handler 测试，以及教师端 outline API 测试；优先扩展这些 seam。
- 不以对真实模型服务发起网络调用作为必需的自动化测试；部署后的模型连通性可另行做手工冒烟验证。

## Out of Scope

- 更换 StepFun、模型名称、供应商、账号或 API 接入方式。
- 修改 PPT 视觉主题、模板目录或 PPTX 渲染策略；本规格中的“本地回退”仅指大纲内容生成。
- 移除或重写本地兜底大纲算法。
- 扩展到讲稿生成、RAG 证据融合、局部修改等其他 AI 调用超时策略。
- 保证外部模型服务一定成功或在固定时间内完成响应。
- 对兜底内容的教学正确性作自动化语义证明。

## Further Notes

- 已观察到的失败表现是 AI Engine 日志记录 `step-5-preview` 请求超时，而 `/gen/outline` 仍返回 HTTP 200；这与服务捕获异常后返回本地兜底大纲的行为一致。
- Go 端 120 秒和前端 150 秒请求预算已在当前工作区调整；实施时应保留这两个边界并核实实际运行进程使用了新配置。
- 验收必须验证真实教师可见的回退状态，而不只验证日志或 AI Engine 内部字段。
- 规格已达到可实施状态；实施者不应将超时加长解释为模型服务可用性保证。
