# S3/S2 课件创作闭环缺口补齐规格

## Problem Statement

当前系统已经具备“新建课件 → S1 意图理解 → S2 资料与证据中心 → S3 课件生成与 AI 修改 → S4 版本、回滚和导出”的主要链路，但图片所描述的完整教师工作流仍有三类缺口：

1. S2 资料、解析切片、个人知识库和证据绑定主要依赖 AI Engine 进程内存，服务重启后不能稳定恢复。
2. 内容修改已经有真实大模型解析和节点级修改链路，但样式类自然语言修改主要由前端规则驱动，尚未形成统一的结构化样式操作。
3. 资料来源汇总、节点引用追溯、历史版本继续编辑和真实 AI/降级状态虽然已有部分实现，但尚未形成可重复验收的端到端闭环。

这些问题会导致教师无法可靠地完成“资料上传并绑定证据 → 生成带引用课件 → 只修改目标节点或样式 → 重启后继续编辑 → 回滚或导出指定版本”。

## Solution

补齐 S2、S3、S4 之间的持久化和证据协议，并统一内容修改与样式修改的结构化处理：

- 为资料资产、解析切片、知识库范围和证据绑定建立持久化边界，并按认证用户和课件项目隔离数据。
- 保留现有上传、解析、检索、证据融合 API，增加持久化恢复和任务状态能力，避免破坏现有前端契约。
- 统一 EvidencePacket、节点来源切片和引用关系，使大纲、内容生成、局部修改、版本快照和 S4 证据追溯使用同一套引用语义。
- 将自然语言样式修改解析为结构化 presentation 操作；样式修改只刷新呈现层，不触发内容 RAG，不改变正文或引用。
- 保证历史版本可预览、可导出、可回滚，并可从指定版本继续进入 S3 对话修改。
- 统一报告真实 LLM、处理中、成功、降级和失败状态，保留降级原因，避免界面静默复位。

## User Stories

1. As a 教师, I want to 创建一个课件项目, so that 我可以从 S1 开始持续编辑同一份课件。
2. As a 教师, I want to 通过多轮对话确认教学意图, so that 后续资料检索和课件生成有稳定的上下文。
3. As a 教师, I want to 上传 PDF、PPTX、DOCX 和视频资料, so that 系统可以从多模态资料中提取教学依据。
4. As a 教师, I want to 查看每个资料的解析状态, so that 我能知道资料是否可以用于生成。
5. As a 教师, I want to 批量上传不属于单个课件的个人知识库资料, so that 后续课件可以复用这些资料。
6. As a 教师, I want to 删除或重新索引资料, so that 知识库内容可以被维护。
7. As a 教师, I want to 按关键词和课件范围检索资料切片, so that 我可以找到与当前教学节点相关的证据。
8. As a 教师, I want to 选择证据片段并绑定到知识点或节点, so that 生成结果能明确说明内容依据。
9. As a 教师, I want to 生成大纲和内容时看到实际引用, so that 我能判断课件内容是否来自正确资料。
10. As a 教师, I want to 让系统只重新生成指定节点, so that 其他节点内容和引用不会被无意修改。
11. As a 教师, I want to 用自然语言要求“整体换成科技感”, so that 系统可以修改模板、配色或版式，而不改动教学内容。
12. As a 教师, I want to 在样式修改时不触发 RAG, so that 样式调整不会浪费检索资源或改变事实引用。
13. As a 教师, I want to 在修改过程中看到处理中、成功、降级或失败状态, so that 我知道是否需要等待、重试或修正指令。
14. As a 教师, I want to 查看每次修改的版本、指令和受影响节点, so that 我可以追踪课件是如何变化的。
15. As a 教师, I want to 预览历史版本并导出指定版本, so that 导出的课件不会误用当前草稿。
16. As a 教师, I want to 回滚到历史版本并生成新的版本号, so that 历史版本不会被覆盖且可以继续编辑。
17. As a 教师, I want to 从历史版本继续进入 S3 对话, so that 我可以在某个稳定版本基础上开展新一轮修改。
18. As a 教师, I want to 重启服务后仍能恢复资料、草稿、版本和引用, so that 工作不会依赖单个进程的内存状态。

## Implementation Decisions

### P0：资料与证据持久化

- 资料资产、解析任务、解析切片、知识库归属和节点证据绑定使用明确的数据边界。
- 所有资源按 `owner_id` 隔离；课件资料额外按 `project_id` 或会话范围隔离。
- 保留现有上传、解析、检索、证据融合端点，优先扩展响应字段，不删除已有字段。
- 向量检索可以继续使用现有混合检索语义，但索引元数据和切片内容必须可从持久化存储恢复。
- 解析失败、部分成功和重试状态必须可查询，单个文件失败不能使同批其他文件不可用。

### P0：统一证据协议

- 每个可引用切片至少包含 `chunk_id`、来源文件、页码或时间范围、文本摘要和知识库范围。
- 每个节点保存 `source_chunk_ids` 和 `citation_refs`；不存在来源时使用空数组，不使用 `null`。
- S2 绑定结果进入课件草稿，并由 S3 大纲、内容生成和版本快照继续传递。
- 内容类修改限定 RAG 检索范围为目标节点；样式类修改不调用 RAG。
- S4 证据追溯展示节点、引用切片和来源文件之间的关系。

### P0：结构化样式修改

- AI 修改接口同时支持内容操作和 presentation 操作。
- 样式操作至少覆盖模板、配色、版式、密度和字体等已存在的呈现字段。
- 样式操作成功后更新草稿、刷新预览并产生新版本。
- 样式操作不得修改正文节点、教学顺序、证据引用或内容生成结果。
- 前端规则匹配只能作为离线/降级兜底，不能作为真实 AI 样式链路的唯一实现。

### P1：版本和恢复体验

- 中间页课件卡片的“继续编辑”恢复同一 `project_id` 的当前草稿和最近生成结果。
- 历史版本预览只读；导出接口必须明确接收并使用选定版本。
- 回滚采用克隆式策略，目标历史版本保留，回滚结果生成新版本号。
- 从历史版本继续编辑时，新的修改记录必须连接到当前项目版本链。

### P1：状态和错误协议

- 生成、解析、修改和导出统一返回可识别的阶段状态。
- LLM 响应保留 `used_fallback`、模型标识和降级原因。
- 前端在请求超时、Abort、404、409、422、500 时保留当前编辑内容并显示可操作错误。
- 版本冲突必须提示当前版本和可选的刷新/合并路径。

### 测试 seam

- 首选一个跨 Go 后端和 AI Engine 的 HTTP 合同 seam，验证请求字段、状态、引用和错误协议。
- 在 AI Engine 内保留 RAG、解析、意图和样式操作的纯逻辑单元测试。
- 在 Go 后端保留版本链、权限隔离、冲突检测和回滚的服务测试。
- 在 Vue 端保留 Store seam，验证状态机、局部节点更新、版本时间线和错误状态。
- 最后使用一个浏览器端端到端 seam 验证教师主流程，不把 UI 快照作为主要验收依据。

## Testing Decisions

- 测试只验证外部行为：API 响应、数据库状态、版本链、节点内容、引用关系和可见 UI 状态，不绑定内部函数实现。
- S2 资料测试覆盖 PDF、PPTX、DOCX、视频四类输入，至少覆盖成功、部分失败、重试和重启恢复。
- RAG 测试验证混合检索、范围过滤、证据融合和引用字段完整性。
- 内容修改测试验证目标节点变化、非目标节点内容与引用不变，以及连续三次局部修改后的逻辑连贯性。
- 样式修改测试验证不触发 RAG、不改变正文和引用、presentation 字段变化并生成新版本。
- 版本测试覆盖 v1 → v2 → v3、回滚生成 v4、历史版本仍可读、指定版本导出和版本冲突。
- 状态测试覆盖真实 LLM 成功、LLM 超时、降级、Abort、404、409 和 500，并验证前端不会静默复位。
- 端到端验收场景为：新建课件 → S1 对话 → 上传资料 → 选择证据 → 生成大纲 → 生成内容 → 局部内容修改 → 样式修改 → 预览 → 回滚 → 指定版本导出。
- 现有 Go、Python 和前端测试作为回归基线；新增测试应优先复用现有 API、Store 和服务测试 seam。

## Out of Scope

- 不重写现有 S1、S3、S4 页面布局，不进行与缺口无关的前端视觉改版。
- 不替换当前大模型供应商，不在本需求中新增模型训练或微调。
- 不实现视频内容理解之外的新型多模态能力，例如实时摄像头、实时语音课堂或视频生成。
- 不改变学生端原有播放、问答和学习进度功能。
- 不删除现有 Mock/Fallback 能力；本需求只要求明确标识并保证真实链路优先。
- 不把历史文档、过程日志或 `.rivet` 产物作为业务代码提交。

## Further Notes

- 当前核心主链路已有较多实现，本规格是“缺口补齐”，不是从零重做 S2-S4。
- 实施前应先确认数据库/向量存储选型和认证用户边界；否则容易出现资料跨用户、跨课件泄露。
- 先完成 P0 的持久化、证据协议和样式分流，再处理 P1 的体验和端到端验收。
- 本规格只代表需求整理结果，尚未授权开始代码实现。
