# PPT 元素级局部修改需求

Status: ready-for-agent

## 1. 目标

教师完成 PPT 生成后，可以通过 S3 Studio 右侧 AI 对话，以自然语言定位并修改 PPT 内的具体元素。修改成功后，系统自动刷新预览、保存课件项目草稿并创建新的正式修改版本；教师可以撤销最近一次修改、查看历史版本、回滚历史版本，并导出保持可编辑性的 PPTX。

## 2. 范围

### 2.1 修改对象

- 页面内标题、正文、列表和教师备注。
- 图片、图表、形状及其位置、大小、颜色、字体和布局属性。
- 元素组，例如图表、图表标题和图表说明。
- AI 生成或替换媒体资源：优先使用教师上传或知识库素材；没有合适素材时允许 AI 检索或生成，但必须经教师确认。

### 2.2 修改动作

- 内容：替换、改写、精简、扩写。
- 结构：新增、删除、合并、拆分、移动。
- 样式：字体、颜色、大小、布局、位置。
- 图片：替换、调整。
- 图表：修改数据、类型和样式。
- 形状：调整颜色、边框、位置和大小。

### 2.3 非目标

- 不允许把页面简单栅格化为图片后冒充元素级编辑。
- 不允许直接使用未确认来源的互联网图片替换课件素材。
- 不允许因单个元素修改失败而保存同一指令的部分结果。

## 3. 目标定位

教师只需输入自然语言，不要求手动填写元素 ID，也不依赖点击选中元素。系统使用页码、元素类型、位置、可见文本和语义内容匹配目标。

当候选不唯一时，系统返回修改候选列表，展示页码、元素类型、位置和摘要，等待教师确认；确认前不得执行修改。

每个元素具有稳定 `element_id`：未删除元素保持原 ID；新增元素生成新 ID；拆分元素生成新 ID 并记录来源关系。

## 4. 元素和元素组

元素至少包含：

```json
{
  "element_id": "el_...",
  "page_id": "page_...",
  "element_type": "text|notes|image|chart|shape|group",
  "role": "title|body|list|caption|data|decoration",
  "content": {},
  "geometry": {"x": 0, "y": 0, "width": 0, "height": 0},
  "style": {},
  "group_id": null,
  "source_refs": [],
  "parent_element_id": null
}
```

元素组用于保持语义和布局关联。结构性操作默认以元素组为单位，并在删除、拆分或大范围移动前提示受影响元素。

## 5. 修改流程

```text
自然语言指令
  -> 目标解析
  -> 唯一目标 / 候选确认
  -> 风险判断
  -> 普通动作直接执行，危险动作二次确认
  -> 原子修改事务
  -> 生成修改后元素树
  -> 刷新预览
  -> 保存草稿
  -> 创建正式修改版本
```

普通文本修改直接执行。删除元素、替换媒体、修改图表数据和批量修改需要二次确认。

一次指令涉及多个元素时必须原子执行：任何目标失败，整次修改不落库，系统返回失败原因和可重试信息。

## 6. 版本、撤销和回滚

每次成功修改保存：

- 修改前完整快照；
- 修改后完整快照；
- 元素树、样式和媒体引用；
- 原始修改指令；
- 父版本关系；
- 实际修改元素和变更摘要。

撤销只针对最近一次对话修改，恢复上一状态并创建新的正式版本，不删除原版本。回滚用于历史版本，采用生成新状态的方式，不覆盖或删除历史。

## 7. 权限

修改、候选查询、草稿读取和保存、版本历史、撤销、回滚、元素读取及导出均必须根据 JWT 推导 `owner_id`。请求体不得声明所有者。访问不存在或不属于当前用户的项目统一返回 `404`。

## 8. PPTX 要求

导出后的 PPTX 必须保持元素可编辑：文本仍是文本框，图表仍是图表，形状仍是形状，图片仍是独立图片对象。修改结果必须在导出的 PPTX 重新打开后可验证。

## 9. 验收场景

1. 生成包含标题、正文、备注、图片、图表和形状的 PPT。
2. 输入“第三页左侧标题改短”，唯一定位后直接修改并刷新预览。
3. 输入“第三页的图片换成 TCP 握手示意图”，系统优先返回已有素材；使用 AI 生成素材时先请求确认。
4. 输入“修改第二页图表数据并改成柱状图”，二次确认后原子完成。
5. 输入指令命中多个候选，系统展示候选，不直接修改。
6. 多元素指令中一个元素失败，整次修改不产生版本、不改变草稿。
7. 撤销最近一次修改后，生成新的正式版本，原历史仍可查看。
8. 回滚历史版本后，生成新的当前版本，历史版本不被覆盖。
9. 刷新浏览器后，草稿、当前版本和 AI 对话上下文仍可恢复。
10. 导出 PPTX 并重新打开，检查文本框、图表、形状和图片仍是可编辑对象。
11. 使用其他用户 JWT 访问修改、版本和导出接口，统一得到 `404`。

## 10. 完成判定

只有当上述流程在浏览器、Go 后端、AI Engine、版本持久化和 PPTX 导出之间完整跑通，并通过元素级导出验证，局部修改功能才算完成。
