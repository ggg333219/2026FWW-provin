# A12 教师端 PRD 缺口闭环

Status: ready-for-agent
Triage: ready-for-agent

## Problem Statement

教师端已经具备 S1-S4 的主要页面和多项生成、资料、版本及导出能力，但 PRD 所列需求分散在不同模块，部分技术方案与当前领域约定或既有规格不一致。仅按文档中的“当前缺失”逐项重做会造成重复实现，也无法证明真实教师工作流已端到端可用。

本规格覆盖 PRD 的 19 项问题及瑞士教育风专项，目标是以教师工作流验收结果为准，补齐未覆盖部分并复用仓库已存在的规格。教师可用文字或语音表达意图，结合平台共享知识库与补充资料形成结构化生成指令集，再生成和修改可编辑课件、配套教案和互动媒体，最终将所选版本可靠导出。

## Solution

围绕一个课件项目贯通 S1 意图澄清、S2 资料与证据、S3 大纲和内容生成、S4 版本与导出。复用已有接口和模块；对照既有规格确定已覆盖范围；仅为尚未覆盖的行为创建新实施任务。验收以外部可观察的教师行为、持久化数据和导出文件为准，不以文档中的现状描述或代码中存在某个组件作为完成证明。

## User Stories

1. As a 教师, I want 通过文字描述教学目标并进行多轮澄清, so that 我能确认完整的教学意图后再生成课件。
2. As a 教师, I want 在支持的浏览器中录音并将转写内容送入同一对话, so that 我可以语音表达教学思路而不丢失对话上下文。
3. As a 教师, I want 在意图解析使用规则降级或失败时看到明确状态和安全原因, so that 我不会把不完整结果误认为模型成功。
4. As a 教师, I want 上传 PDF、Word、PPT、图片和视频资料, so that 可解析的教学内容能参与当前课件生成。
5. As a 教师, I want 让上传资料与主题、知识点或内容格式要求建立关联, so that 系统能按我的意图使用资料内容和参考样式。
6. As a 教师, I want 从平台共享知识库检索候选证据, so that 全体授权教师可以复用持久化教学资料。
7. As a 教师, I want 知识库资料、索引和状态在服务重启后保留, so that 重启不要求重新灌入资料。
8. As a 教师, I want 在 S2 搜索、筛选和分页查看全部候选证据, so that 我不受前十条结果限制。
9. As a 教师, I want 明确勾选本次课件可使用的证据片段, so that 未确认资料不会被自动当成引用依据。
10. As a 教师, I want 查看证据的来源、页码或时间信息, so that 我可以核对生成内容的依据。
11. As a 教师, I want 一份结构化生成指令集汇总意图、资料提取、已确认片段和输出要求, so that 下游大纲、PPT、教案和互动生成使用一致上下文。
12. As a 教师, I want 生成指令集随项目草稿和生成结果留存, so that 刷新、重启和后续版本可恢复生成依据。
13. As a 教师, I want 在 S3 选择“内容生成”或“全流程生成”模式, so that 我可以只生成已确认大纲的内容，或从意图开始重跑完整链路。
14. As a 教师, I want 大纲生成较慢时看到持续进展且避免服务层提前超时, so that 我不必因请求超时而接受质量较差的兜底大纲。
15. As a 教师, I want 大纲回退时明确看到来源和原因, so that 我可判断是否需要重试或手动修订。
16. As a 教师, I want 手动编辑、添加、删除和排序大纲节点并保存, so that 我可在生成内容前控制课件结构。
17. As a 教师, I want 默认生成封面和总结页，并在满足规则时生成目录页, so that 课件具有完整教学结构。
18. As a 教师, I want PPT 内容不重复展示仅供组织大纲的内容概述, so that 页面呈现聚焦于实际教学内容。
19. As a 教师, I want 真正逐页生成并看到当前页的处理状态, so that 我可以分段生成并检查页面结果。
20. As a 教师, I want 选择疏密级别并在预览和 PPTX 中看到一致版式, so that 内容密度调整不会造成预览与导出不一致。
21. As a 教师, I want PPT 内容页包含与知识点相关的图片或图示, so that 课件表达不局限于纯文本。
22. As a 教师, I want 优先使用本地图库，缺少合适素材时尝试 LLM 生图, so that 配图链路在离线环境仍有可用路径。
23. As a 教师, I want 生成配套 Word 教案并包含教学目标、教学过程、教学方法、课堂活动和课后作业, so that 我能获得完整备课材料。
24. As a 教师, I want 教学方法、课堂活动和课后作业在 Word 中以醒目的大字号标题呈现, so that 新增板块容易检查和使用。
25. As a 教师, I want Word 导出任务能结束于明确的成功或失败状态并提供可下载文件, so that 导出不会无限停留在处理中。
26. As a 教师, I want 生成至少一种可运行的 HTML5 互动内容, so that 学生可在浏览器中参与知识点活动。
27. As a 教师, I want 将生成的 GIF 或视频作为媒体嵌入 PPT 页面并随 PPTX 一并导出, so that 演示文稿包含可播放的动画或视频，而不只是外部链接。
28. As a 教师, I want 将 HTML5 互动课件独立导出, so that 交互行为不受 PPT 媒体能力限制。
29. As a 教师, I want 将 HTML5 互动资产与同一课件版本关联, so that 预览和下载使用同一生成结果。
30. As a 教师, I want 在 S4 预览课件并通过自然语言提出调整顺序、简化页面或增加案例等修改, so that 我可以迭代到满意版本。
31. As a 教师, I want 导出的 PPTX 和 DOCX 对应我明确选中的课件版本, so that 下载结果不被其他草稿或版本替换。
32. As a 教师, I want 新建或恢复课件时草稿严格按课件项目隔离, so that 不会看到其他项目的缓存内容。
33. As a 教师, I want 登录页使用本产品文案, so that 产品身份与教师工作流保持一致。
34. As a 教师, I want 预览界面不再展示早期 HTML5 mock 框, so that 我看到的是实际生成的课件或互动资产。
35. As a 教师, I want 选择瑞士教育风后预览与导出呈现一致的完整版式, so that 该主题不只是更换颜色。
36. As a 维护者, I want 新需求与既有规格有明确映射和依赖, so that 相同能力不会被重复开发或产生冲突契约。

## Implementation Decisions

### Scope and Sequencing

- 本规格包含 PRD 全部 19 项问题和瑞士教育风专项；采用分阶段交付，但瑞士风属于本需求范围，不因后置而删除。
- 教师端为范围主体；不新增学生端功能，不重做与本规格无关的视觉设计。
- PRD/技术方案中的现状、根因、代码行号和工时是待核验材料，不视为已经验证的实现事实。
- 实施前应逐项映射既有规格和当前代码行为；已覆盖能力复用既有规格，只对未覆盖的验收结果新增任务。

### S1 and Shared Knowledge

- 语音输入复用现有教师意图对话，支持浏览器能力检测；不支持时提供明确的不可用状态并保留文字输入。
- 意图解析成功、规则降级和失败应可区分、可诊断；错误展示不得泄露密钥、请求头或内部堆栈。
- “本地知识库”在本需求中指部署在本项目环境中的**平台共享知识库**，授权教师可复用；不是每位教师私有库，也不是单机临时索引。
- 资料原件、切片、来源映射、向量索引及任务状态必须可从持久化存储恢复；具体存储复用项目现有持久化架构，不把 pickle 或进程内状态作为唯一数据源。
- 教师补充资料按平台共享知识库的既有权限和资料治理约定入库；本次课件只使用教师明确确认的片段。
- S2 候选证据搜索、筛选和分页必须覆盖完整结果集；列表分页不能截断可选范围。

### Generation Instruction Set

- 生成指令集是一次生成的统一结构化输入，至少包含教学意图、参考资料提取、已确认证据及引用、PPT/教案/互动输出要求、呈现偏好和生成模式。
- 同一指令集供大纲、逐页内容、教案及互动生成使用；不能只在大纲调用时临时拼接 prompt。
- 指令集进入课件项目草稿，并随生成结果/版本快照留存；更新草稿不能改写已完成版本的历史指令集。

### S3 Generation and Media

- 两种生成模式通过同一 S3 工作区中的模式选择控件和同一生成操作触发：内容生成只根据已确认大纲生成或更新页面内容；全流程生成从意图和资料融合开始并重建大纲与内容。
- 大纲生成采用可观察的进展/结果状态；服务间超时预算必须由内向外递增。兜底结果仍可编辑，但必须标注真实来源。
- 大纲可手工编辑、增删和排序，并通过现有持久化契约保存；版本冲突不得静默覆盖。
- 封面和总结页默认生成；目录页按已确认的规则生成，规则和教师覆盖方式在实现任务中保持一致且可测试。
- “内容概述”仅作为组织/讲稿上下文，不得被当作 PPT 正文重复渲染。
- 逐页模式对每个目标节点执行真实内容生成，单页状态、失败重试和已完成页面保留均可观察。
- 密度参数使用一套规范值映射到预览和 PPTX；遗留的 `compact/comfortable/loose` 与 `minimal/standard` 命名差异必须在契约层统一，不让 UI 参数只触发重绘样式。
- 配图优先匹配随服务部署的本地/内置图库；无合适素材时尝试可用的 LLM 生图能力。生图不可用或失败时保留无图生成能力并显示安全状态；图片不能依赖不稳定的外网 URL 才能打开。
- 互动 HTML5 是独立可运行产物。动画 GIF/视频作为媒体嵌入 PPTX 的对应幻灯片并随 `.pptx` 自包含导出；不能用 hyperlink 占位冒充嵌入。媒体加载失败须影响导出状态，不得报告完整成功。
- PPTX 产物质量验证复用既有导出质量规格；DOCX 生成和状态完成另行验收。

### DOCX, S4, and Product Cleanup

- 配套教案包含教学目标、教学过程、教学方法、课堂活动设计和课后作业；新增三个板块标题采用醒目大字号（目标 14 pt）并验证导出文档实际样式。
- Word 异步导出必须进入成功或失败终态，关联正确版本和可下载地址；失败可重试且不伪报成功。
- S4 使用既有版本链、预览和修改合同；本规格不重做已由元素级修改规格覆盖的自然语言定位、版本快照和撤销语义。
- 草稿读写统一使用课件项目身份，避免全局缓存跨项目恢复；登录文案更换为本产品身份；移除早期 HTML5 mock 预览但保留真实资产预览。

### Swiss Education Visual System

- 瑞士教育风列入当前总需求，安排在核心生成、资产与导出链路之后实施。
- 保持预览和 PPTX 导出共用的页面规格路径；不得另建 HTML 截图嵌入分支。
- 贯通主题 ID 与导出请求；定义版式参数和调色板；补齐验收约定的核心教学布局；对预览与导出做同内容对照。
- 外部文档估算约 56 人天与分阶段小计并不完全一致；估算只作初排参考，实施拆分时重估。

### Existing Specification Mapping

- S1/S2/S3 AI Engine 意图、RAG 范围、互动生成和 HTML5 链路：复用 `.scratch/member-b-ai-engine/spec.md` 中适用部分。
- S2-S4 资料持久化、证据协议、项目草稿和状态：复用 `.scratch/s3-gap-completion/spec.md`，并遵循本规格明确的平台共享知识库边界。
- S3 大纲超时与回退状态：复用 `.scratch/s3-outline-ai-fallback/spec.md`；本规格仅补充全流程逐节点可见和跨阶段指令集要求。
- S3 自然语言内容/样式修改、版本迭代和 PPT 元素修改：分别复用 `.scratch/s3-ai-iteration/spec.md`、`.scratch/s2-version-iteration-loop/spec.md` 与 `.scratch/ppt-element-modification/spec.md`，不得重复定义版本身份或元素 ID 契约。
- PPTX 文件本身的结构质量闸门：复用 `.scratch/s3-pptx-export-quality/spec.md` 及其任务；新增媒体嵌入要求扩展该导出 seam，但不替代质量闸门。
- 新建 issue 仅覆盖现有规格未涵盖的语音/意图可观测性、共享知识库与指令集的契约对齐、S3 生成模式与版式/配图、DOCX 成品及其完成状态、GIF/视频媒体嵌入、草稿隔离/品牌/Mock 清理、瑞士风端到端落地等内容。

## Testing Decisions

- 所有测试验证外部行为和交付物，不绑定私有函数或某一种内部组织方式。
- 主要验收 seam 为浏览器中的教师工作流，使用确定性 AI、知识库和媒体 fixture；验证 S1 输入/确认、S2 证据选择、S3 模式生成/大纲编辑/预览、S4 选定版本导出和下载。
- AI Engine 使用确定性 stub 验证意图成功/降级/失败、生成指令集传递、证据筛选完整性、逐页生成、教案字段、互动资产和媒体失败行为；不把真实外部模型服务作为必需 CI 依赖。
- Go/API 合同测试验证用户/项目边界、超时/降级字段透传、指令集和版本快照持久化、导出状态终态及所选版本。
- 持久化验收写入共享知识库资料和向量索引，重启 AI Engine/Go 服务后重新检索并验证来源与内容仍存在；不得用仅检查文件存在替代查询验证。
- DOCX 验收打开导出包并检查五个教案板块、三处醒目标题样式、版本和下载状态。
- PPTX 验收打开导出包并验证页面结构、嵌入 GIF/视频的媒体 part 与 slide relationship 存在且媒体字节可读；媒体须被实际嵌入 PPTX，不接受只有外链。HTML5 验收在浏览器打开并验证交互内容可用。
- 预览与导出视觉一致性覆盖标准密度和全部支持主题；瑞士风在同一内容下对照预览和 PPTX。
- 语音自动化测试通过 stubbed SpeechRecognition 验证文本回填与对话提交；Chrome/Edge 实际麦克风能力另做浏览器冒烟，不把自动测试权限模拟当成硬件验收。
- 使用既有 AI Engine pytest、Go handler/service 测试与教师端 Vitest 作为回归先验；当前教师端没有现成 Playwright E2E 命令，浏览器 seam 需在任务拆分中确定可复用的自动化工具与运行方式。

## Out of Scope

- 学生端功能、学生播放/问答/进度和与教师课件创作无关的旧泛雅业务。
- 更换大模型供应商、模型训练/微调、实时视频生成或实时课堂视频处理。
- 多人协同编辑、并发冲突自动合并或完整的新 PPT 可视化编辑器。
- 以 GIF/视频替代 HTML5 交互；嵌入式媒体不被描述为可点击互动。
- 对所有第三方 PowerPoint/WPS 版本、字体环境和播放器做绝对视觉一致性保证。
- 无关的教师端视觉重设计、后端重构或全仓库清理。

## Further Notes

- 本规格由 PRD、技术方案 v1.1、用户澄清及仓库 CONTEXT/ADR/既有规格共同整理；用户确认了范围与主要产品决策。
- 本规格是需求发布，不等同于实现授权；实现前需要核查既有规格与当前工作树中的代码/测试，尤其是技术文档声称缺失但已有初步组件或契约的条目。
- 项目术语“生成指令集”已补入 `CONTEXT.md`；“平台共享知识库”继续使用既有术语，技术方案中“个人/私有库”假设不适用于此范围。
- 既有工作规格保持原文不覆盖；如实现前发现其明确假设与本次已确认决策冲突，应在对应 issue 中追加决策说明并协调状态，不能静默照旧实现。
