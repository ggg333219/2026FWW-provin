## 二、本次完成后端项目全景解释（功能性理解）

### 2.1 三层协作中 Go 后端本次承担了什么

本次改动**只落在 Go 教师后端**，Python AI Engine 与 Vue 前端零改动。补齐的是 Go 网关中 S3（课件生成）主链路缺失的**大纲业务层**——即"教师确认大纲 → 大纲成为内容生成的输入"这段状态管理。

```
Vue 教师端 (已就绪，outlineApi.js / outlineStore.js)
   │  HTTP /api/v1/outlines/*（本次实现前 → 404 / 编译不过）
   ▼
Go 教师后端 (本次补齐)
   ├── OutlineHandler      ← HTTP 入口，5 端点
   ├── OutlineService      ← 业务规则：状态机 / 校验 / 版本链
   ├── OutlineStore        ← 持久化抽象
   │     ├── gormOutlineStore  → Postgres（outline_versions 表，完整模式）
   │     └── memOutlineStore   → 进程内存（S1 standalone 降级）
   ├── ContentHandler      ← /gen/content 三端点（内容生成入口）
   └── ai_engine_client.go ← 补 5 个 DTO + 2 个接口方法
   │
   ▼  HTTP（Python 侧为纯函数，无状态）
Python AI Engine
   ├── POST /gen/outline         （OutlineBuilder.build）
   └── POST /gen/outline/revise  （OutlineBuilder.revise）
```

### 2.3 大纲状态机与版本语义

```
draft ──confirm(校验通过)──► confirmed ──被修改──► superseded（旧版，只读保留）
  ▲                            │
  └────── PUT 保存新版本 ───────┘
        (confirmed 版本被修改 → 旧版 superseded，新版回 draft 可重新确认)

创建(version=1, draft) → 保存(version++) → 确认(status=confirmed)
                                    → GetConfirmed 供生成任务注入节点
```

关键业务规则：
- **outline_id + outline_version 唯一**确定一份大纲（复合主键）。
- **确认后不可原地覆盖**——对 confirmed 大纲的任何保存都生成新版本号，旧版本留痕。
- **auto_apply=false 的 AI 修订**返回待确认候选（预置下一版本号但不落库），前端确认后以 PUT base_version=候选号 提交——这是 outlineStore 的 revise→apply 流程的后端对应。
- **GetConfirmed** 只放行 confirmed 状态版本，供 `GenerationHandler.Create` 把大纲节点注入生成任务（generation_handler.go 原引用点），且拒绝未确认大纲（409 语义）。

### 2.4 存储策略（两种启动模式）

`cmd/teacher/main.go` 有两条启动路径，OutlineService 用 store 接口兼容两者：

| 模式 | 触发 | store | 持久性 |
|---|---|---|---|
| 完整模式 | Postgres 可用 | gormOutlineStore（outline_versions 表，AutoMigrate 建表） | 跨重启 |
| S1 standalone | Postgres/MinIO 不可用 | memOutlineStore（进程内存 + RWMutex） | 仅当次进程 |

### 2.5 对前端的契约承诺（对齐 outlineApi.js / outlineStore.js）

- 响应统一 `{"code":200,"data":{...}}`（前端 request.js 要求 `payload.code===200` 才不抛错）。
- data 结构含 outline_id / outline_version / status / title / nodes[] / session_id / intent_id / confirmed_at——与 outlineStore `_applyOutlineData` 逐字段对齐。
- status 三态（draft/confirmed/superseded）；前端本地 `confirming` 为过渡态，不落库、后端不返回。
- OutlineNode 字段 snake_case，含 order（前端校验依赖 order 连续）。
