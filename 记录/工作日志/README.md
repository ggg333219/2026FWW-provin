# 工作日志 — 规则

## 为什么需要工作日志

汇报是"做完了才写"，但日常沟通不能等做完。**工作日志解决两个问题：**

1. **队友想知道你当前在做什么** → 看你的日志就知道了，不用问
2. **合并时想知道这一轮发生了什么** → 扫一遍所有人日志就知道了

## 怎么写

在你的专属文件里，**按时间往上加**（最新的在最上面）：

```markdown
## 2026-07-18

### 上午
- [P4-B1] 完成了大纲构建骨架
  - 文件：ai_engine/gen/outline.py
- ⚠️ 发现 python-pptx 不支持内联 CSS，模板得用 XML 改

### 下午
- [P4-B2] 节点生成器写了一半
  - @A 同学 节点的数据结构定了，你看看接口能不能对齐
- ❓ intent 里如果有多张图片，怎么传给节点？待确认
```

## 标记约定

| 标记 | 含义 | 示例 |
|------|------|------|
| `[P4-B1]` | 关联到任务包中的任务 ID | `[P4-B1]` = Phase 4, B 的第 1 个任务 |
| `@A` | 需要某人注意 / 行动 | `@A 同学 接口定好了你看看` |
| `⚠️` | 风险、踩坑、重要注意 | 列在日志中方便合并时汇总 |
| `❓` | 未解决的问题、待确认 | 合并时协调人看到会处理 |
| `✅` | 某件事确认完成 | 用于标记子任务状态 |

## 频率

- **不要求每天写**，但每次**实质性干活**后花 1 分钟追加一条
- 写多了别人不看，**1-3 行最好**，只写关键信息和变更
- "今天研究了 X 方案但没做出来" — 这也值得写，因为队友需要知道你在卡什么

## 合并时

协调人会读每个人的日志，提取关键信息汇总到 `看板/README.md` 的"本轮合并摘要"。所以：

- 你写了 → 协调人就能看到
- 你不写 → 你做的事在合并时就丢了
- 标记 `@某人` → 协调人会确保他收到信息
