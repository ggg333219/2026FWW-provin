## 一、项目背景与目标

### 1.1 赛题信息

| 项目 | 说明 |
|------|------|
| 赛题编号 | A12 |
| 赛题名称 | 多模态 AI 互动式教学智能体 |
| 主办方 | 锐捷网络 · 服务外包赛题 |
| 参赛形式 | 团队赛（4人） |

### 1.2 核心目标

将现有的"泛雅 AI 智课系统"（讲授型课件 + 学生 Q&A）重构为**多模态 AI 互动式教学智能体**，实现以下核心流程：

```
教师输入需求 → 多轮对话澄清 → 上传多模态参考资料
      ↓
系统解析（PDF/PPTX/视频/图片）
      ↓
RAG 知识库检索 + 证据融合
      ↓
生成课件初稿（PPT/Word/互动）
      ↓
教师预览 → 修改命令 → 再生成
      ↓
锁定版本 → 导出成品
```

### 1.3 技术架构

项目为三层物理架构：

```
┌──────────────────┐     HTTP REST     ┌──────────────────┐     HTTP REST     ┌─────────────────────┐
│   Vue Frontend   │ ◄──────────────► │   Go Backend     │ ◄──────────────► │   Python AI Engine  │
│  (教师端 + 学生端) │                   │  Gin + GORM      │                   │  FastAPI + LLM      │
│                   │                   │  + Redis + MinIO │                   │  + RAG (pgvector)   │
└──────────────────┘                   └──────────────────┘                   └─────────────────────┘
```

- **Go 后端**：API 网关 + 业务逻辑 + 数据层（会话、版本、导出）
- **Python AI Engine**：LLM 调用、多模态解析、RAG、课件生成、PPT/DOCX 导出
- **Vue 前端**：教师端（Vue 3 + Vite）和学生端（Vue 2 + Vue CLI）

## 三、S3 数据与接口规范（v1.0，2026-09-03）

这是本次开发的核心契约文档，定义了 S3 课件生成阶段的数据模型、字段命名、状态枚举和 HTTP API。

### 3.1 ID 命名规则

```
session_id
  → intent_id
  → outline_id + outline_version
  → generation_id
  → version_id
  → page_id + node_id
  → interactive_asset_id
```

### 3.2 状态机

**大纲状态**：`draft` → `confirmed` → `superseded`（确认后不可覆盖，修改生成新版本）

**生成任务状态**：`pending` → `processing` → `partial_done` → `done` | `failed`

**生成阶段**：`outline` → `evidence` → `content` → `interactive` → `page` → `preview` → `done`

### 3.3 核心 API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/outlines` | 生成大纲 |
| GET | `/api/v1/outlines/:outline_id?version=N` | 获取大纲 |
| PUT | `/api/v1/outlines/:outline_id` | 保存大纲版本 |
| POST | `/api/v1/outlines/:outline_id/revise` | AI 修改大纲 |
| POST | `/api/v1/outlines/:outline_id/confirm` | 确认大纲 |
| POST | `/api/v1/gen/content` | 生成内容（独立阶段） |
| POST | `/api/v1/generations` | 创建生成任务（支持 outline_id/outline_version/outline_confirmed） |
| GET | `/api/v1/generations/:generation_id` | 查询生成状态 |
| POST | `/api/v1/generations/:generation_id/pages/:page_id/regenerate` | 单页重生成 |
| POST | `/api/v1/generations/:generation_id/pages/:page_id/revise` | AI 修改页面 |
| POST | `/api/v1/generations/:generation_id/nodes/:node_id/interactive` | 生成互动资源 |
| GET | `/api/v1/interactive/assets/:asset_id` | 查询互动资源 |

## 四、工具使用说明

### 4.1 Git 使用规范

#### 团队协作原则

1. **不强制推送（force push）**：所有人禁止对 main/develop 分支做 force push
2. **小步提交**：每个功能点完成就 commit，方便回退
3. **先 fetch 再 merge**：合并前先拉取远程最新代码

#### 同步远程最新代码

```bash
# 方式一：直接 pull（推荐，用于日常同步）
git pull origin main

# 方式二：先 fetch 再 rebase（保持线性历史）
git fetch origin
git rebase origin/main
```

#### 遇到 "历史分叉" 时的处理

远程 force push 后（如本次 .claude 清理），本地分支与远程分叉：

```bash
# 查看分叉状态
git status
# 输出：Your branch and 'origin/main' have diverged, and have 3 and 52 commits respectively.

# 解决方案：强制同步到远程最新
git fetch origin
git reset --hard origin/main
```

#### 分支管理建议

```bash
# 开发新功能前从 main 创建功能分支
git checkout -b feat/my-feature

# 开发完成后提交 PR，请求合并到 main
# （PR 需要至少 1 位队友 review 后再合并）
```

#### 提交信息规范

参考 conventional commits：

```
feat: 新功能
fix: 修复 bug
docs: 文档更新
chore: 构建/工具变更
refactor: 重构
test: 测试相关
```

示例：


## 九、附录

### 9.1 常见问题排查

**Q：Go 后端编译报错 "undefined: OutlineNode"**
A：`OutlineNode` 定义在 `ai_engine_client.go` 中，检查 import 是否正确引入 `smart-teaching-backend/internal/service`。

**Q：AI Engine 启动报错 "module 'xxx' not found"**
A：执行 `pip install -r requirements.txt`，确保 Python 版本 3.10+。

**Q：前端 npm run dev 报 "module not found: vue"**
A：执行 `npm install` 安装依赖。

**Q：导出下载返回 400 Bad Request**
A：检查 `ExportHandler.Download` 白名单（`export_handler.go:75`），当前支持 `pptx`/`docx`/`html`。

**Q：版本回滚后页面数据不更新**
A：前端需要在回滚成功后重新调用 `GET /api/v1/version/:gen_id` 刷新版本快照。
