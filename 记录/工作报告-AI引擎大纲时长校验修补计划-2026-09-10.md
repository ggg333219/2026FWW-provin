# AI Engine 大纲时长校验修补计划

> 日期：2026-09-10
> 问题：生成大纲失败：大纲结构校验失败：AI 生成大纲无效：节点 `node_001` 时长必须大于 0。
> 范围：仅修补 `ai_engine` 侧大纲生成与修订链路；Go 网关校验规则保持不变。

## 一、问题定位

当前 Go 网关 `backend/internal/service/outline_service.go` 的 `validateOutlineNodes` 要求每个节点的 `estimated_duration_minutes > 0`。但 Python AI Engine 的 S3 大纲契约存在字段断裂：

1. `ai_engine/schema.py:build_stage2_node_tree_schema` 的节点 Schema 没有声明 `estimated_duration_minutes`。
2. `ai_engine/gen/outline.py:_run_node_tree_generation` 的提示词明确要求 LLM 只输出少量字段，也没有要求节点时长。
3. `ai_engine/schema.py:normalize_stage2_nodes` 没有补齐或归一化节点时长，因此 LLM 输出进入 Go 后被 JSON 映射为 `0`。
4. `OutlineBuilder._fallback_outline` 同样没有生成 `estimated_duration_minutes`，导致 LLM 失败时的兜底结果也无法通过 Go 确认校验。
5. `OutlineBuilder.revise` 沿用相同的缺失字段风险，修订后再次提交可能复现问题。

结论：这不是单个 `node_001` 的脏数据，而是 Python 大纲输出契约没有覆盖 Go 确认接口必需字段。Go 的“时长必须大于 0”校验是有效约束，应由 AI Engine 在生成边界补齐可用值。

## 二、修补目标

- Python 生成、兜底、修订三条路径都输出正数 `estimated_duration_minutes`。
- 节点时长总和尽量与意图中的 `duration_minutes` 一致；未提供课时或输入非法时使用稳定默认值。
- 不改变 Go 的状态机、确认校验和 API 契约。
- 保持旧版 Python 单测中对节点基础字段的兼容，不把讲稿字段混入大纲。
- 通过真实的 `POST /gen/outline` 响应检查，确保结果可直接提交 Go `/api/v1/outlines/:id/confirm`。

## 三、实施步骤

### 1. 补齐 AI Engine 大纲输出 Schema

修改 `ai_engine/schema.py`：

- 在 `build_stage2_node_tree_schema` 的节点属性中增加 `estimated_duration_minutes`。
- 类型使用 number，约束为大于 0；保留为可选字段以兼容旧 LLM 响应，再由归一化层统一补齐。
- 如当前 LLM Provider 对 JSON Schema 的 `minimum` 支持不稳定，允许 Schema 做类型约束，正数校验放在 Python 归一化函数中完成。

### 2. 在归一化层统一补齐时长

修改 `normalize_stage2_nodes` 或在 `ai_engine/gen/outline.py` 增加专用的时长分配函数：

- 优先读取节点已有的 `estimated_duration_minutes`。
- 兼容旧字段 `duration_minutes`，必要时兼容 `estimated_duration`。
- 将字符串、空值、`0`、负数、NaN 和无穷值视为无效，不把它们透传给 Go。
- 对无效节点分配正数默认值（建议每节点 5 分钟）。
- 当上下文提供 `duration_minutes` 时，按节点数量进行正整数分配，并确保每个节点至少 1 分钟；余数分配到前几个节点，避免总时长变成 0 或与课时严重偏离。
- 归一化后的字段名固定为 `estimated_duration_minutes`，不再依赖下游隐式默认。

建议接口形态：

```python
def normalize_stage2_nodes(
    nodes: list[dict[str, Any]] | None,
    total_duration_minutes: int | float | None = None,
) -> list[dict[str, Any]]:
    ...
```

如不希望扩大现有公共函数参数，则在 `OutlineBuilder` 内先调用基础归一化，再调用 `_assign_node_durations`，但三条入口必须复用同一套规则。

### 3. 贯通意图课时到大纲构建

修改 `ai_engine/gen/outline.py`：

- `build` 从 intent 读取 `duration_minutes`，传入时长分配逻辑。
- `_run_node_tree_generation` 的 prompt 明确要求每个节点输出 `estimated_duration_minutes`，并说明单位为分钟、必须大于 0、总和应接近课程总时长。
- LLM 返回后统一执行时长归一化，不信任模型直接满足正数约束。
- `build_from_markdown` 无 intent 课时时使用默认总时长，例如 45 分钟。
- `_fallback_outline` 直接写入正数时长，并按 key_points 数量分配，确保 LLM 不可用时仍可被 Go 确认。
- `revise` 保留原节点时长；新增节点按剩余课时或默认值补齐，删除节点后重新归一化总时长，保证修订结果仍满足约束。

### 4. 统一节点类型契约

在本次修补中一并确认 Python 到 Go 的 `node_type` 映射：

- Python 目前允许 `slide`，Go 确认校验允许 `content`，两侧枚举并不完全一致。
- 不在本问题中修改 Go 规则，但 AI Engine 输出给 Go 的大纲应将默认类型收敛为 Go 契约允许的值（建议 `content`），或在网关适配层完成明确映射。
- 增加测试覆盖，避免修复时长后出现下一条 `node_type 非法` 错误。

### 用例 C′：修订路径 —— 发现并修复一个真实缺陷

配好密钥后重跑修订，**错误变了**：从 401 变成 `大纲修订失败: 'list' object has no attribute 'get'`。这说明 LLM 已经能返回内容，暴露出的是代码缺陷。

**根因（两层）：**

1. `ai_engine/core/llm.py:149` 的 `extract_json` 只查找 `{`…`}` 区间。`chat_with_schema` 的三级降级链在②③级（`response_format=json_object` / 纯 prompt 约束）不强制根节点为 object，模型可能直接返回裸数组。裸数组时三级全部解析失败，整条链路抛 `RuntimeError`。
2. 即便解析成功，调用方写的是 `result.get("nodes")` / `result.get("scripts")`。`result` 为 list 时直接 `AttributeError`，且该异常被上层 `except` 吞成兜底内容，表现为静默的质量塌方。

**修复：**

- `ai_engine/core/llm.py`：`extract_json` 改为按最先出现的括号判定根形状，`{}` 与 `[]` 都能解析，解析失败再退回另一种；原「对象优先」行为不变；返回类型放宽为 `Any`。
- `ai_engine/schema.py`：新增 `extract_list_payload(result, *keys)` 与 `extract_nodes_payload(result)`，容忍 dict（按 key 取）与 list（直接用）两种根形状，并过滤非 dict 元素。
- `ai_engine/gen/outline.py`：`revise` 与 `_run_node_tree_generation` 两处改用 `extract_nodes_payload`。
- `ai_engine/gen/node.py`：两处 `result.get("scripts")` 改用 `extract_list_payload`。
- `ai_engine/generator.py`（已标记 DEPRECATED）：其私有 `_extract_json` 复制了同一份「只认 `{}`」逻辑，改为委托给共享实现；两处 `.get("scripts")` / 一处 `.get("nodes")` 一并改用共享 helper。

## 六、风险与处理

| 风险 | 处理 |
|---|---|
| LLM 严格 Schema 不接受可选/最小值组合 | Schema 只约束 number，Python 归一化负责最终正数保证 |
| 课时字段未从 Go 请求传给 Python | Python 使用默认 45 分钟；同时检查 Go `GenOutlineRequest` 到 Python `GenOutlineRequest` 的字段透传 |
| `slide` 与 `content` 类型不一致 | 在 AI Engine 输出边界统一为 Go 可接受类型，补充契约测试 |
| 修订后节点数量变化导致总时长失真 | 修订完成后重新执行统一时长分配，并保留原节点时长作为优先输入 |
| 旧测试依赖节点字典精确结构 | 只增加契约字段，不删除已有兼容字段；对精确断言逐项更新 |
