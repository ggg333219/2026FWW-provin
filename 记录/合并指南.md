# 合并指南

> 每次有人要把分支合并到 main 时，按此流程操作。

## 核心原则

**合并不只是合代码，更是合信息。** 合并完成后只看 `记录/` 下的文件，就能知道这一轮发生了什么。

## 合并前检查清单

每个分支在合并到 main 之前，分支作者必须：

- [ ] 代码检查：`go build ./...` 或 `python -m pytest ...` 通过
- [ ] 工作日志：自己的 `工作日志/` 已更新，包含本轮所有关键事项
- [ ] 汇报：如果完成了子任务，对应的 `汇报/` 已新建文件
- [ ] 看板：自己的 `看板/` 已更新任务状态
- [ ] 决策日志：如果有方案选择，是否写了决策日志？
- [ ] 接口变更：如果改了接口契约，是否通知了受影响的人？

## 合并流程

### 第一步：依次合并（按依赖顺序）

```
先合 A（Go 后端） → 再合 B（Python AI） → 最后合 C（Vue 前端）
```

因为 B 依赖 A 的接口，C 依赖 A 的 API。

### 第二步：合并后 — 协调人更新看板

1. 读一遍每个人的 `工作日志/`，提取关键事件
2. 读 `汇报/`，确认完成的任务
3. 读 `决策日志/`，确认有没有新决策影响全局
4. 更新 `看板/README.md`：
   - 更新"总体进度"进度条
   - 更新各人任务表的状态
   - 在"本周合并摘要"追加一条本轮合并记录

### 第三步：合并摘要格式

每次合并后在 `看板/README.md` 的"本周合并摘要"追加：

```markdown
### 2026-07-18 合并（batch-push → main）

**A - Go 后端**
- A1 死代码清理 ✅
- A2 compat_student.go 拆分 🚧 进行中（完成 60%）

**B - Python AI**
- P4-B1 大纲构建 🚧 开始开发
- 发现 python-pptx 中文字号问题 ⚠️

**C - Vue 前端**
- C1 清理 ✅
- C2 路由框架搭建 🚧

**新决策**
- D-002: pgvector 而非专用向量数据库

**下一轮关注**
- A 同学完成后通知 B 联调接口
- C 同学等到 A 的 API 再继续
```

## 解决冲突

**记录/ 下的文件按人分区，理论上是零冲突的。** 如果合并时 `看板/README.md` 冲突（协调人同时改了），只需保留最新版本即可——因为各人进度表是分开的文件，README 只是汇总。

## 紧急修复

如果线上有 bug 需要绕过流程：
1. 修复分支命名：`hotfix/xxx`
2. 修复后补填工作日志和汇报
3. 合并后立即更新看板
