# 记录系统 — 3 分钟上手

> 4 人并行开发的"信息中枢"。每次合并时扫一眼这里，就能抓住所有人做了什么。

## 四类文件，管三个维度

```
时间轴                             谁写的
──────────────────────────────────────────
工作日志/   ← 日常流水，按天追加       每个人写自己的
汇报/      ← 子任务完成总结           每个人写自己的
看板/      ← 当前状态总览            每个人维护自己的行，协调人汇总
决策日志/  ← 方案选择记录             谁决策谁写
```

| 维度 | 什么时候写 | 写什么 | 给谁看 |
|------|-----------|--------|--------|
| **我在做什么** | 每天 / 每次干活 | `工作日志/` 追加一条 | 队友（同步进度） |
| **我做完了什么** | 子任务完成 | `汇报/` 新建一页 | 协调人（验收） |
| **为什么这么选** | 有方案选择 | `决策日志/` 新建一页 | 全队 + 答辩 |
| **现在做到哪了** | 状态变化 | `看板/` 更新自己的行 | 全队（一眼了解全局） |

## 每个人在哪写

| 你的人 | 工作日志 | 汇报 | 看板 |
|--------|---------|------|------|
| A - Go 后端 | `工作日志/A-后端.md` | `汇报/A-后端/` | `看板/A-进度.md` |
| **B - Python AI 引擎** | **`工作日志/B-AI引擎.md`** | **`汇报/B-AI引擎/`** | **`看板/B-进度.md`** |
| C - Vue 前端 | `工作日志/C-前端.md` | `汇报/C-前端/` | `看板/C-进度.md` |
| 协调人 | — | — | `看板/README.md` 汇总 |

## 日常节奏

### 🕐 每次干活时 → 写工作日志

```markdown
## 2026-07-18

### 上午
- [P4-B1] 完成了大纲构建模块
  - 核心逻辑：接收 intent → 生成 outline → 拆成节点
  - 文件：ai_engine/gen/outline.py
- ⚠️ python-pptx 对中文支持有坑，字号映射需要单独处理

### 下午
- [P4-B2] 开始节点生成，已有骨架
- ❓ 多轮对话的结果怎么传给生成器？接口还没定
```

**写日志的约定：**
- `[任务ID]` — 关联到任务包（P4-B1、A2 等）
- `@某人` — 需要他注意 / 等他接
- `⚠️` — 风险 / 踩坑
- `❓` — 未解决的问题
- 每条 1-3 行，写多了没人看

### ✅ 子任务完成时 → 写汇报

```yaml
---
task_id: P4-B1
title: 大纲构建模块
status: completed
summary: 完成了 outline_builder，输入 intent 输出结构化大纲
changes:
  created:
    - ai_engine/gen/outline.py
affects: B
next: P4-B2 节点生成
---
详细过程（选填）...
```

汇报模板在 `汇报/README.md`，复制就填。

### 📊 状态变化时 → 跟新看板

去 `看板/B-进度.md`，把对应任务的 ⬜ 改成 🚧 或 ✅。

### 📝 有方案选择时 → 写决策日志

> 为什么用方案 A 不用方案 B？写下来。答辩会问。

### 🔄 合并前 → 读合并指南

`合并指南.md` 告诉你每一步做什么。

## 一句话原则

> **日志保日常 → 汇报保节点 → 看板保全局 → 决策日志保历史。**
> 各自写各自的文件，永远不会冲突。
