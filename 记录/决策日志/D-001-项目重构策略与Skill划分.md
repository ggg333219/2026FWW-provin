## D-001 2026-07-14 - 项目重构策略与 Skill 划分方案

### 背景

泛雅 AI 智课系统需要重构为"多模态 AI 互动式教学智能体"以满足锐捷网络赛题要求。
原系统核心链路为"课件解析→讲授脚本生成→学生问答→进度续接"，新系统要求为
"教师需求输入→多轮对话澄清→多模态参考融合→课件生成→预览修改→导出成品"。

项目跨度大（涉及前端/后端/AI Engine/文档多层面），需要拆分为可独立推进的单元。

### 可选方案

**方案 A：4 个功能模块平铺（直接按系统功能拆分）**
- 意图理解 / 多模态交互 / 课件生成 / 个性化满足各成模块
- 知识库作为横向支撑
- 优势：与题目要求直接对齐
- 劣势：模块间边界不够清晰，存在交叉依赖

**方案 B：按依赖关系分层（3 层递进）**
- 底层：意图理解 + 知识库（可并行）
- 中层：多模态交互 + 课件生成
- 上层：个性化满足 + 导出
- 优势：层间依赖清晰
- 劣势：底层未完成前上层无法开始

**方案 C：5 阶段 + 4 Skill + Workflow 编排（最终选型）**
- Stage 1-5 按阶段推进
- 4 个 Skill 各司其职，知识库横切
- 每个阶段内部使用 multi-agent 并行编排
- 优势：可以独立并行推进，进度可视化，可验证

### 决策结论

**采用方案 C**（5 阶段递进 + 4 Skill + 知识库 + ultracode 编排）。

理由是：
1. 用户明确要求"拆成很多个工作流，把步骤拆分开来做"
2. 项目有多位队友协作，需要明确的阶段里程碑
3. 4 个 Skill 的划分与赛题评分点直接对应，便于答辩时说明
4. ultracode 的 multi-agent 编排可以最大限度并行推进

### 影响范围

- 整体：项目按 5 阶段组织，产出记录统一放在 `记录/` 目录下
- **界面重构**：教师端工作台需要全部重新设计（对话→上传→预览→导出）
- **后端新增**：Conversation/Agent Orchestrator/Version/Export 四大模块
- **AI 扩展**：视频解析、Word 生成、PPT 导出、RAG 四大能力
- **知识库**：需要收集专业知识库资料并建立 RAG 链路
- **团队**：前端/后端/AI 可并行开发，通过接口契约对齐

### 验证方式

1. Phase 1 综合报告评审 → 确认对项目的认知一致性
2. Phase 2 架构设计评审 → 确认 4 Skill 边界合理性
3. Phase 3 前后质量对比 → 确认耦合度降低
4. Phase 4 每个 Skill 独立测试通过 → 确认功能完整性
5. 最终端到端流程跑通 → 确认整体可用
