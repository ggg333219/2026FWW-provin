# 决策日志

## 用途

记录本项目二次开发全过程中所有**关键决策、方案选择、设计讨论及其依据**。
用于终期答辩时追溯设计思路，确保"从头到尾的决策过程有记录可查"。

## 怎么用？

1. 遇到**方案选择**（比如"用 A 方案还是 B 方案"、"这个接口怎么设计"）
2. 确定结论后，**复制下方模板**创建一个新文件
3. 文件命名：`D-{编号}-{简短标题}.md`，如 `D-002-会话状态机设计.md`
4. 填完后在下方**索引表**加一行

### 决策记录模板

```markdown
## D-{序号} {日期} - {决策标题}

### 背景
为什么需要做这个决策？当前面临什么问题或约束？

### 可选方案
列出考虑过的方案及各自优劣势。

### 决策结论
最终选择的方案及理由。

### 影响范围
该决策影响哪些模块/文件/团队分工。

### 验证方式
如何验证该决策是正确的？（测试用例/评审/指标）
```

### 什么时候该写

- 技术选型（用 A 库还是 B 库？）
- 接口设计（这个 API 的路径、参数怎么定？）
- 架构调整（模块拆分方式、目录结构）
- 方案取舍（方案 A 简洁但扩展性差，方案 B 相反）
- **如果不确定要不要写——就写**。答辩时决策记录是加分项。
