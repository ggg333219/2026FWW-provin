## 3.1 算法创新设计总体思路

本项目并非简单地将大语言模型接入备课流程。大模型的生成能力在本系统中被视为**一种不稳定但可用的能力来源**，算法设计的核心命题由此确定：

> **如何通过工程结构与教学规则，把模型输出的不确定性约束在可接受范围内，并使每一步生成结果可追溯、可修改、可回退。**

围绕这一命题，算法体系在四个方向上作出升级：

**（1）从"一次成稿"到"分层收敛"**
放弃"输入描述 → 直接产出完整课件"的单次生成路径，将生成过程拆分为大纲层、内容层、样式层三层。每层只解决一类问题，且**前一层的确认是后一层的前置条件**。由此把一次不可控的端到端生成，转化为三次可控的局部决策。

**（2）从"指令补全"到"状态驱动的意图收敛"**
教师的初始表达通常是模糊的（如"我想讲机器学习入门"），缺少教学对象、课时、重难点、教学方式等生成必需信息。系统不要求教师学习提示词写法，而是以"收集—澄清—确认—锁定"的状态机逐步收敛意图，最终固化为结构化的 `IntentSummary`，作为后续所有生成环节的唯一输入。

**（3）从"附件级资料"到"页面级证据"**
教师上传的 PDF / Word / PPT / 图片 / 视频，在传统流程中仅作为附件存在。本系统将其解析为可检索的内容切片，经由混合检索与重排后形成 `EvidencePacket`，并进一步**绑定至具体的教学节点与页面**。由此，每一页生成内容都能回答"依据了哪份资料的哪一部分"，且教师可对证据进行选择与舍弃。

**（4）从"模型输出即结果"到"结构化输出 + 校验 + 兜底"**
对所有面向生成的接口建立 Schema 约束与字段完整性检查，并通过规则模板在模型输出异常时进行兜底，避免单次生成失败导致整个流程中断。同时将部分教学设计规则算法化（课时分配、节点类型识别、教学目标组织、教学阶段划分），使模型生成受到明确的教学结构约束。

## 3.2 需求获取与算法设计依据

### 3.2.1 需求获取方法

本系统的算法设计采用**"教师场景痛点分析 + 赛题要求映射 + 技术可行性验证"**三条线索交叉确定，避免算法设计与实际使用场景脱节。

| 线索 | 输入 | 输出 |
|------|------|------|
| 教师场景痛点分析 | 备课流程拆解（教学构思 → 资料整理 → 课件制作 → 教案编写 → 互动设计 → 反复修改） | 需要被算法解决的具体卡点 |
| 赛题要求映射 | 本地知识库、多模态需求输入、意图理解与知识融合、多模态生成、迭代优化与导出 | 算法能力的边界与验收口径 |
| 技术可行性验证 | 部署资源约束、异步处理能力、模型调用成本 | 算法实现方式（异步/批处理/降级） |

### 3.2.2 算法设计的工程约束

算法方案并非在理想条件下设计，以下约束直接决定了若干实现选择：

| 约束 | 对算法设计的直接影响 |
|------|---------------------|
| 服务器资源受限 `【待补-2：具体配置，如 CPU/内存/GPU 情况】` | 资料解析等重任务不得阻塞主服务，转入异步队列执行 |

| 备课跨时段进行 | 必须支持断点续编与状态持久化 |

## 3.4 关键算法设计

### 3.4.1 教学意图的状态化收敛

**问题**：生成质量的上限取决于输入信息的完整度，而教师的初始表达天然不完整。

**约束**：不能要求教师学习结构化提示词；追问轮数必须收敛，不能无限问答。

**机制**：定义四状态意图机，系统依据当前信息完整度决定是继续追问、返回澄清结果，还是进入锁定。

| 状态 | 进入条件 | 系统行为 | 迁出条件 |
|------|---------|---------|---------|
| 收集 | 教师首次表达教学想法 | 抽取已有意图要素，识别缺失项 | 存在必需缺失字段 |
| 澄清 | 存在必需缺失字段 | 按优先级选择**单一**缺失项提问（一次一问） | 该字段被填充 |
| 确认 | 必需字段齐备 | 向教师回显 `IntentSummary` 草稿，请求确认或修改 | 教师显式确认 |
| 锁定 | 教师确认 | `IntentSummary` 冻结，作为后续生成唯一输入 | 版本迭代时部分解锁 |

`IntentSummary` 的字段构成 `【待补-6：请提供 IntentSummary 的实际字段列表与类型，我需要用一张字段表替代此处的占位描述。这是本书中最能体现"结构化"的一张表。】`

**为什么一次只问一个问题**：多问题并行会显著提高教师的回答成本并导致回答质量下降。系统将缺失字段按"对生成结果影响权重"排序 `【待补-7：排序规则是固定优先级还是模型动态判断？】`，逐项澄清，使追问轮数可控。

**形式化表达**：设必需字段集合为 $F = \{f_1, f_2, \dots, f_n\}$，当前已获取集合为 $F_t \subseteq F$。状态机的推进条件为：

$$F \setminus F_t = \varnothing \;\wedge\; 确认信号 \Rightarrow \text{Locked}$$

即：**当且仅当缺失字段集为空且获得显式确认，意图才进入锁定。**

**未知字段处理**：若某项信息教师明确表示"不清楚"，系统不得以空值阻塞流程，须写入默认值并标记为"教师未指定" `【待补-8：默认值策略是什么？例如课时缺省时如何分配？】`，由后续生成环节按缺省规则处理。

### 3.4.2 多模态资料解析与页面级证据绑定

**问题**：教师已有资料（PDF / Word / PPT / 图片 / 视频）数量多、格式杂，传统做法是将其作为附件整体投喂，导致两个后果：一是上下文被无关内容稀释，二是生成内容无法说明来源。

**机制**：分三个阶段处理。

**阶段一 · 异步解析**
教师上传后，Go 后端写入资料元信息并生成解析任务标识，将任务投递至 Redis 队列；Python AI Worker 出队执行解析，结果写回数据库与对象存储，前端通过轮询或回调获取状态 `【待补-9：请确认最终采用的回调/轮询方式，以及是否使用 SSE】`。

> **图 3-X　多模态资料异步解析数据流图**
> `【待补-10：需提供此图，建议包含：教师上传 → Go 写元信息 → 生成解析任务 → Redis 入队 → Python Worker 出队 → 分格式解析 → 写回 DB/对象存储 → 前端取状态】`

不同格式采用不同解析路径：

| 资料类型 | 解析产出 | 备注 |
|---------|---------|------|
| PDF / Word | 文本 + 页面结构 + 标题层级 | `【待补-11：是否保留图片与表格？如何处理？】` |
| PPT | 按页提取文本、备注、图形元素 | 页面天然可作为切片单位 |
| 图片 | `【待补-12：是否做 OCR / 图像理解？产出什么？】` | |
| 视频 | `【待补-13：抽帧策略、是否转录音频、摘要粒度】` | 当前能否定位到时间轴？见第 7 章边界 |

**阶段二 · 混合检索**
所有解析结果统一切片并建立索引。检索时并行执行两路召回：

- **向量召回**：捕获语义层面的相关（"遗传算法"与"GA"、同义表述）
- **BM25 召回**：保证专有名词与术语的精确命中

两路结果合并后经重排得到候选证据集。

`【待补-14：这是本节最需要的四个参数——切片粒度（chunk size / overlap）、embedding 模型与维度、两路召回的 top-K、融合方式（RRF 还是加权？权重如何确定？）】`

**为什么必须两路并行**：单一向量召回对专有名词、缩写、公式符号的区分能力弱；单一 BM25 无法处理同义与上下位表述。教师资料中存在大量术语变体，任取一路都会在召回环节丢失可用证据。

**形式化表达**：给定查询 $q$（由当前教学节点与 `IntentSummary` 共同构造），候选证据 $e$ 的相关性得分为：

$$score(q, e) = \alpha \cdot S_{vec}(q, e) + (1-\alpha) \cdot S_{bm25}(q, e)$$

或采用倒数排名融合 $RRF(q,e) = \sum_{r \in R} \frac{1}{k + rank_r(e)}$ `【待补-15：实际采用哪一种？$\alpha$ 或 $k$ 的取值及调参依据】`

**阶段三 · 页面级证据绑定**
检索结果不直接进入生成上下文，而是先组织为 `EvidencePacket`，绑定至 `TeachingNode` 与具体页面：

`【待补-16：请提供 EvidencePacket 的实际结构与绑定规则，我需要写成一张字段 + 绑定/解绑条件表】`

由此教师可在页面上查看"这一页用了哪几份资料的哪几段"，并逐条选择或舍弃。这一步把资料从"投喂给模型的附件"变成"教师可控的生成依据"，也是本系统在可追溯性上区别于通用工具的关键设计。

## 本章小结

本章四个算法方向中，**意图收敛**解决"输入不完整"，**证据绑定**解决"依据不可见"，**分层生成**解决"过程不可控"，**校验兜底**解决"输出不可靠"。四者共同回答一个问题：如何在大模型能力不稳定的前提下，产出教师敢用、敢改、能追溯的教学成果。
