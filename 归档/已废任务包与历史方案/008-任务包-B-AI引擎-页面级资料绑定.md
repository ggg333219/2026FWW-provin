## 任务分解

### B-1. 新增 `auto-bind-pages` 端点（页面级自动绑定入口）⭐

**目标**：S3 工作台进入时（onMounted）调用此端点，基于 `intent_id` + 当前 outline 的 page 列表，对每个 page 自动 RAG 检索并预填默认 evidence。

**文件**：
- 新增：`ai_engine/main.py` 新增 `POST /api/v1/intent/{intent_id}/auto-bind-pages`
- 新增：`ai_engine/rag/router.py` 新增 `auto_bind_pages(intent_id: str, outline_id: str) -> dict[page_id, list[chunk_id]]`
- 扩展：`ai_engine/core/schema.py` 新增 `AutoBindPagesRequest/Response`（参照已有 `SearchRequest` 模式）

**实现要点**：
1. 请求体：`{ intent_id, outline_id, top_k_per_page: int = 5, min_score: float = 0.2 }`
2. 服务端逻辑：
   - 从 Redis 取出 `IntentSummary`（用 `intent_id`）→ 拼 query（`topic + audience + objectives + duration_minutes`）
   - 从 outline 取所有 page_id 列表
   - 对每个 page_id，调 `HybridRetriever.search(scope="page", page_id=...)` 取 top-k chunks
   - 合并 chunks 为 `PageEvidenceBinding`（标记 `auto_bound=true`, `bound_by="system:intent_keyword"`）
   - 写入 Redis 持久化（key 形如 `page_bindings:{outline_id}`，与 HANDOFF.md Phase 2 P5 的 `_session_parsed_chunks` 旁路一致）
3. 响应：`{ page_bindings: { page_id: PageEvidenceBinding }, missing_pages: [] }`（检索失败的 page 列出，让前端提示教师上传）

**验证**：
- 单测 `ai_engine/tests/test_auto_bind_pages.py`：
  - **RED**：写一个测试，固定 IntentSummary + 3 个 page_id + mock store 返回固定 chunks → 调用 `/api/v1/intent/{id}/auto-bind-pages` → 期望返回 3 个 `PageEvidenceBinding`，每个 `evidence_refs` 长度 = top_k
  - **GREEN**：实现端点逻辑直到通过
  - 反例：min_score=0.99 + mock store 全低分 → 返回 `missing_pages: [所有 page_id]`
- 端到端：`curl -X POST http://localhost:8000/api/v1/intent/test-intent/auto-bind-pages -d '{"intent_id":"test-intent","outline_id":"test-outline"}'`

**完成标志**：
- 端点可被 `teacherV1Api`（前端）调用
- 单元测试 `pytest ai_engine/tests/test_auto_bind_pages.py -v` 全绿

### B-3. per-page evidence 持久化（HANDOFF Phase 2 P5 落地）

**目标**：把自动绑定结果 + 教师手动绑定 + 教师解绑操作持久化到 Redis，避免重启丢失。

**文件**：
- 扩展：`ai_engine/rag/router.py:282`（已有 `_session_parsed_chunks`，旁路加 `_page_bindings`）
- 扩展：`ai_engine/core/redis_client.py` 新增 `set_page_binding / get_page_bindings / delete_page_binding` 方法
- 新增：`ai_engine/tests/test_page_binding_persistence.py`

**实现要点**：
1. Redis key 约定：`page_bindings:{outline_id}` → JSON `{ page_id: PageEvidenceBinding }`
2. 三个操作接口：
   - `set_page_binding(outline_id, page_id, binding)`：单页写入
   - `set_page_bindings_bulk(outline_id, bindings_dict)`：批量写入（B-1 自动绑定用）
   - `get_page_bindings(outline_id) -> dict[page_id, PageEvidenceBinding]`
   - `delete_page_binding(outline_id, page_id)`：教师解绑用
3. 与现有 `_session_parsed_chunks` 的关系：sessions 按 `intent_id` 分组，page_bindings 按 `outline_id` 分组；同一个 page 可被多个 outline 版本绑定，存最新版即可（旧版本走 VersionHandler 快照，见 A-4）

**验证**：
- 单测 `pytest ai_engine/tests/test_page_binding_persistence.py -v`
  - RED：写 `set_page_bindings_bulk` + `get_page_bindings` 往返测试，期望 JSON 完全一致
  - RED：写 `delete_page_binding` 后 `get_page_bindings` 不含该 page
  - GREEN：实现直到通过

**完成标志**：
- 与 A-4 的 VersionHandler 快照逻辑解耦清晰（VersionHandler 独立存，不依赖 Redis key 格式）

- 复用：`ai_engine/generator.py` 的逐页生成函数（`generate_page_content` 之类，需先 grep 确认函数名）

**实现要点**：

   - 用 `evidence_refs` 调 `KnowledgeStore.list_chunk_by_ids(refs)` 取 chunks（沿用 commit 1577a82 的 `list_chunk_ids` 抽象接口）

   - 输出携带 `citation_refs: evidence_refs`（即"用了哪些证据"）

  - GREEN：实现直到通过
