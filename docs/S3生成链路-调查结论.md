## 1. 一句话结论

S3 存在**三条**生成路径，它们不是同一份契约的三种包装：`/gen/content`（讲稿）、`/gen/create`（全流程）、`/gen/modify → /gen/content(partial)`（S4 局部）在证据注入、意图传递、大纲节点传递、结果覆盖四个维度上都不同。决赛演示**建议固定走 `/gen/create`**，另外两条只作辅助展示。

## 2. 三条路径对照

| 维度 | ① `/gen/content` 讲稿 | ② `/gen/create` 全流程 | ③ S4 局部 `/gen/modify` |
|---|---|---|---|
| 教师操作 | 「📝 生成全部节点讲稿」 | 「🚀 开始生成」 | 版本里选中页面做局部修改 |
| 生成内容 | 仅节点讲稿 | 大纲 + 讲稿 + 页面 | 只重写目标节点 |
| 请求里的资料 | `generation_instruction_set.confirmed_evidence` | `evidence_packet` | `evidence_refs`（chunk_id） |
| `intent` / `context_markdown` | 前端**不传** | `intent` 传；`markdown` 空 | Go 不传 `intent`；Python 由绑定证据生成 `partial_context` |
| 讲稿 Prompt 里的资料 | 本次修复前**无** | 有（`_evidence_brief`） | 有（`_load_page_evidence`） |
| `outline_nodes` | 发出但 Go/Python 结构体未声明 → **静默丢弃** | `createGeneration` 未解构 → API 层丢弃，靠 `instruction_set.outline_nodes` 兜底 | 不适用 |
| 结果覆盖 | `contentStore.nodesContent`，`editedNodeIds` 防覆盖手改 | `loadGenerationStatus` 用 `withEditedScripts()` 盖回讲稿；`full_pipeline` 还会覆盖已确认大纲 | `mergePartialResult` 只合并目标节点 |
| 版本落盘 | 不落 | 管道内 `save_snapshot` | 修改后另存版本 |

**预览 / PPTX / Word 的数据源不一致**：S3 HTML5 预览用内存 `currentScriptNodes` inline 传给 `/gen/preview`；S4 预览用版本快照走前端本地 Blob；**PPTX / DOCX / HTML5 导出由前端显式把 `exportVersionNodes` 作为 `nodes` 回传，Python `export_create` 在 `req.nodes` 非空时优先使用且不校验与所选版本是否一致**。表中「结果覆盖」「数据源不一致」相关项即第 10 节列为后续独立任务的内容，本 PR 未改。

## 5. 决赛演示规避口径（不改代码也能做）

1. 主线固定走 **「⚙️ 全流程生成」（`/gen/create`）**；生成范围保持默认 `content_only`，**不要现场切 `full_pipeline`**（会重建大纲、覆盖教师手改内容）。
2. 按固定顺序跑通：大纲确认 → 讲稿生成 → 全流程生成 → **显式点一次「保存新版本」** → 进 S4。每一步的 Tab 都是硬门禁，跳步会灰掉。
3. 演示「无资料」时从 **S2 的无证据确认弹窗** 进入，或用自动检索失败 gate 里的「仅按 S1 意图生成」；**不要**用 S3 侧栏「取消全选 / 暂不使用」，那两个不改 `generationMode`（B1）。
4. 每一次修改后显式保存版本，确认显示「已保存 vN」再导出 —— 否则预览是新内容、PPTX/DOCX 是上一版。
5. 演示前清 `localStorage.fuww_mock_mode`；全程盯 Network 真实响应体。本次修复后，断网时保存/修改/导出会**明确报错**而不是假成功（**L3 断网模拟已实测**）。
6. 导出后核对文件大小与内容；Word 教案要确认来源不是 `fallback` / `mock`。
7. 统一走 `project_id` 通道，避开 `gen_id` 通道可能缺失的 AI Engine 次快照。
