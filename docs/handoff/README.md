## 推荐的新会话开启方式

1. 把 [新会话初始提示词.md](./新会话初始提示词.md) 里的**「三、本项目专用版」**整段作为新会话的第一条消息；
2. 助手会先做只读检查并回报环境现状；
3. 你确认后，助手再按交接文档第 7 节把环境跑起来、开始工作。

## 顺序为什么是这样

- **先提示词、后文档**：提示词负责设定"允许做什么 / 什么算证据 / 遇到分歧怎么办"，
  交接文档负责提供"具体做了什么、怎么复现、哪些坑别踩"。
  两者互补，缺一不可 —— 只有交接文档，助手不知道该守什么边界；
  只有提示词，助手没有项目事实。

- **交接文档自包含**：新会话**不应该**需要"去问上一个会话的人"才能继续。
  凡是能写下来的都要写下来，尤其是**踩过的坑**和**被否决的方案**。

## 维护约定

- 每次向远程推送功能提交后，**同步更新**本目录下的交接文档
  （提交 SHA、验证结果、遗留问题、踩坑清单）。
- 新发现的坑请直接追加到交接文档的「踩坑清单」一节 —— 那里是本项目最贵的资产。
