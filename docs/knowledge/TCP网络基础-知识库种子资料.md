## TCP 三次握手

TCP 三次握手用于建立可靠连接并同步双方的初始序列号。

1. 客户端向服务端发送 `SYN=1, seq=x`，客户端进入 `SYN-SENT`。
2. 服务端回复 `SYN=1, ACK=1, seq=y, ack=x+1`，服务端进入 `SYN-RECEIVED`。
3. 客户端回复 `ACK=1, seq=x+1, ack=y+1`，双方进入 `ESTABLISHED`。

第三次 ACK 让服务端确认客户端已经收到服务端的同步响应，也能降低旧的、延迟到达的 SYN 被误判为新连接的风险。

## TCP 四次挥手

主动关闭方发送 FIN；被动关闭方先 ACK 确认，待自身数据发送完毕后再发送 FIN；主动关闭方回复最后一个 ACK 并进入 TIME-WAIT。TIME-WAIT 通常持续 2MSL，用于确保最后的 ACK 有机会重传，并让旧连接报文在网络中消失。

## 可靠传输

- 序列号与确认号：每个字节属于序列空间，累计确认表示接收方期望的下一个字节。
- 超时重传与快速重传：发送方根据 RTT 估算重传超时，多个重复 ACK 可触发快速重传。
- 校验和：检测 TCP 首部与数据在传输中的比特错误。
- 有序交付：乱序数据先缓存，缺口补齐后再按序交付应用。

## 流量控制与拥塞控制

流量控制通过接收窗口 `rwnd` 避免发送方压垮接收方；拥塞控制通过拥塞窗口 `cwnd` 避免向网络注入过多数据。实际可发送窗口通常受 `min(rwnd, cwnd)` 限制。
