## 2. 本次迭代完成内容（已落地功能 / 修复问题）

### 2.1 落地：后端预览持久化接口（M2-1）

原 `GET /api/v1/gen/preview/{gen_id}` 路由不存在，预览仅依赖内存任务与前端本地缓存，刷新页面即丢失，无法演示"生成→预览→修改→再生成"闭环。

落地：新增该路由，统一从**版本快照（磁盘）**读取节点（与 `POST /api/v1/gen/preview` 的 gen_id 路径同源），支持 `version` 参数加载指定历史版本；节点序列化后经 `PreviewRenderer` 渲染，返回 `html / node_count / generation_id / version_number / nodes`。由于生成管道完成前必写磁盘快照，该接口**跨进程重启有效**，已实测：重启后同一 gen_id 仍返回 6 节点与完整 HTML。

### 2.2 完成：导出文件 WPS 兼容性实测（M2-2）

对 `PPTExporter` 导出的 3 页测试文件（封面 / 内容 / 小结，含 segments 分段数据）在 WPS 12.1.0.28505 实测。

落地：人工打开 WPS 复核确认三页正常显示；并改用 **WPS COM 自动化接口（KWPP.Application）** 逐页核验——`Slides.Count=3`、每页经 WPS 渲染引擎导出 PNG 做像素级验证（封面深蓝底 #245B78 + 白字、内容/小结浅底 #F5F8FA + 正文）。过程中排除了一次"WPS 打开瞬间白屏截图"的误判（加载时序问题，非文件问题），最终三页全部通过，报告与截图已归档 `docs/WPS验证/`。

### 2.3 修复：S1→S3 intent 字段断链（"未命名课件"空输出根因）

真实 LLM 全链路验证时发现：S1 意图摘要使用 `topic / knowledge_points` 字段，而大纲生成器 `OutlineBuilder.build` 读取 `title / description / key_points`，字段对不上导致标题退化为"未命名课件"、节点近乎空提示。

落地：在 `build` 入口做一次字段归一化——`title`（缺省回退 `topic`，再缺省才用"未命名课件"）、`description`（回退 `subtitle`）、`key_points`（回退 `knowledge_points`）；证据包兼容 `relevant_chunks` 与 `chunks` 两种字段名。修复后同一意图产出 6 个真实节点（定义 / 配方法 / 公式法+判别式 / 因式分解 / 二次函数关系 / 增长率应用）。

### 2.4 修复：生成管道事件循环阻塞（真实 LLM 下全接口卡死根因）

此前 `_run_generation_pipeline` 由 `asyncio.create_task` 调度，而管道内部是同步 LLM 调用，真实生成 30–60 秒期间**整个事件循环被阻塞**，`gen/create`、`gen/status`、`/health` 全部超时（Go 代理表现为 `exit 28` / "context deadline exceeded"）。mock 模式瞬时完成，此问题长期被掩盖。

落地：管道改为同步函数，锁改为 `threading.Lock()`，由 `threading.Thread(daemon=True)` 执行；状态查询用 `with _gen_tasks_lock` 读取。修复后实测：`gen/create` 0.12 秒返回，生成期间 `gen/status` 全程 200 可查（进度 10%→30%→50%→100%），事件循环不再被拖死。

### 2.5 落地：StepFun 真实 LLM 全链路验证

配置并验证真实 LLM 提供方：`.env` 写入 StepFun 密钥 / `step_plan/v1` / `step-3.7-flash`，健康检查确认 `llm configured / mode=llm / degraded=false`。完成 `gen/create → status 轮询 → 版本快照落盘 → 预览接口` 端到端跑通，快照 `data/versions/course_*/v_1.json` 落盘 6 节点且全部带 segments，预览接口返回 6 节点与完整 HTML。

### 2.6 落地：单元测试补齐

新增 intent 归一化单元测试 9 例（S1 字段映射、title 优先级、双缺失兜底、空要点不崩溃、LLM 空结果/异常回退、证据包 `relevant_chunks`/`chunks` 双字段注入）；定向回归 `test_outline_intent_normalization + test_preview + test_version` 共 **71 例全部通过**。

## 3. 当前模块现存可发现问题 & 未完全解决的遗留隐患

以下为代码跑完验证后仍客观存在的隐性/边界问题，均如实记录：

1. **生成任务状态为进程内字典，进程重启即丢失。** `_gen_tasks` 是模块级内存 dict，AI Engine 重启后 `gen/status` 返回 404；预览虽已走磁盘快照不受影响，但任务的进度/阶段查询无法跨重启恢复。

2. **daemon 线程直接修改 task 对象属性，状态读取存在弱竞态。** 管道线程在锁内取到 task 引用后，直接改 `task.status / task.nodes / task.progress_pct`，`gen_status` 在锁内取引用、锁外读属性。CPython GIL 下属性读写原子、当前风险低，但读 `nodes` 列表这类容器时可能读到替换过程中的中间态。

3. **真实 LLM 单次生成耗时过长且进度不细化。** 6 节点生成约 3 分钟，其中"逐节点生成"阶段（`NodeGenerator.generate_all` 单次批量 `chat_with_schema` 产出大 JSON）长期停留在 50% 不动，前端进度条观感差；无流式输出、无分节点进度回传。

4. **LLM 单次调用无超时上限，失败整体回退。** `LLMClient` 吞异常返回兜底，但单次调用无超时控制，网络挂起会拖住整个 daemon 线程且不释放；批量生成一次失败即整体回退兜底脚本，缺少"按节点重试 / 降级为单节点生成"的策略。

5. **真实配置缺自检，队友环境易误配。** `.env` 在仓库根且 gitignore，新成员 clone 后默认模型是 `qwen-turbo`（StepFun 不存在），`/health` 仅显示 `degraded=false` 但不校验模型有效性，真实调用时才会暴露 404，误导排障。

6. **`task_id` 与 `generation_id` 双 ID 并存，存在混淆隐患。** 内存任务以 `task_id` 为键，预览/快照以 `generation_id` 为键；`gen/create` 同时返回两者，若前端任一处混用（用 task_id 查预览、或用 generation_id 查 status），会得到 404 或空结果。

7. **intent 归一化只在 OutlineBuilder.build 入口兜底。** 前端 S3StudioPage 仍原样透传 S1 意图，依赖后端归一化；若未来新增生成入口不复用 `build`（如 `build_from_markdown` 或其他管道），断链风险仍在；且 `title > topic` 的优先级只是实现选择，未与 S1 语义文档化约定。

8. **WPS 验证覆盖有限。** 只实测了固定 3 页测试文件与本机中文字体环境，未覆盖真实 6 节点生成文件、无目标字体的回退表现、文件打开速度；`KWPP.Application` 依赖 WPS 已安装，无 WPS 的 CI 环境无法自动化回归。

9. **测试存在并发与真实链路缺口。** 无针对 daemon 线程改造的并发用例（如并发 create + status）；`test_all` 等真实 LLM 用例依赖网络与密钥，无法离线/CI 运行；归一化测试仅覆盖 mock 路径。

10. **事件循环修复未覆盖全部同步 LLM 调用点。** 本次仅处理了 `_run_generation_pipeline`；`gen/patch.py`、`gen/commands.py`、`gen/interactive.py` 等模块的同步调用若被其它 async 端点直接调用，仍可能再次阻塞事件循环，需逐端点审计。

## 5. 后续可优化方案 & 迭代建议

针对第 3 章现存问题，逐条给出成对的优化思路：

1. **任务状态内存态** → 复用仓库已有 `redis_client.py` 任务持久化，将任务状态/阶段/进度写入 Redis，重启后按 `task_id` 恢复；或沿用版本快照思路，任务完成后落一份轻量状态 JSON 到 `data/`。
2. **daemon 线程弱竞态** → 状态读取同样在 `with _gen_tasks_lock` 内完成（含读 `nodes` 容器），或改为不可变快照式更新（每次替换整个 task 对象而非就地改属性），彻底消除读到中间态的可能。
3. **生成耗时与进度** → `generate_all` 由单次批量改为**逐节点生成 + 每节点回传进度**（按节点数均匀切分 50%→100%）；对 LLM 启用流式输出（StepFun OpenAI 兼容接口支持 SSE），首个节点产出即可回显。
4. **无超时/无按节点重试** → 给 `chat()` 增加超时上限（如 90 秒）；批量生成失败时按节点降级为 `generate_single` 重试，仍失败才用单节点兜底，避免整批回退。
5. **配置缺自检** → `/health` 增加模型有效性探测（启动时发一次最小 chat 校验，失败即标记 `degraded=true` 并给出"模型不存在 / 密钥无效"的明确原因）；`.env.example` 补充 StepFun 套餐说明，团队新成员按模板配置。
6. **双 ID 混淆** → 前端统一约定：`status` 查询用 `task_id`、预览/快照用 `generation_id`；后端在 `gen/create` 响应与文档中明确两者语义，必要时在前端封装 `useGeneration` 统一收敛。
7. **归一化只兜底 build 入口** → 将字段归一提取为独立工具函数（如 `normalize_s1_intent`），前端 S3StudioPage 在透传前先归一，后端保留兜底；把 `title > topic` 优先级写入 S1 语义约定文档，避免未来改动漂移。
8. **WPS 验证覆盖有限** → 用真实 6 节点生成文件补一轮 WPS 实测；补充"移除目标字体"场景验证回退；把 WPS COM 核验脚本化（现有 KWPP 自动化可复用），作为可重复的回归步骤纳入文档而非仅一次性截图。
9. **并发/真实链路测试缺口** → 为 daemon 线程改造补并发单测（mock LLM 下同时发起 create 与多个 status，断言事件循环延迟低、状态一致）；真实 LLM 用例加 `@skipUnless(env 有密钥)` 标记，本地手动跑、CI 跳过，避免 CI 挂死。
10. **同步 LLM 调用点未全审计** → 全项目扫描 async 端点内是否有同步 `chat*` / `embed` 调用，凡涉及 LLM 的端点统一改为 daemon 线程 + 线程锁模式，形成"LLM 调用禁止在事件循环内同步执行"的代码规约。

## 6. 本次开发总结

**开发难点**：本次最大的难点是**隐性根因定位**。真实 LLM 全链路第一次跑就被 Go 代理超时、health 无响应、预览空输出三个症状同时卡住，而它们在 mock 模式下全部正常——最终分别定位到两个被掩盖的根因：`OutlineBuilder` 字段断链（S1 意图字段与大纲生成器字段不一致）导致"未命名课件"空输出；`asyncio.create_task` 里混入同步 LLM 调用导致事件循环被真实生成拖死。同步代码混在异步框架里、mock 掩盖真实路径，是排障成本最高的两类问题。

**收获**：掌握了"异步框架内同步阻塞的线程化解耦"模式（`threading.Lock` + daemon 线程，锁内取引用、锁外读对象的弱竞态权衡）；打通了 StepFun OpenAI 兼容接口的真实接入（含 `chat_json / chat_with_schema` 的 json_schema 约束）；沉淀了"字段归一化 + 多级兜底"的防御式适配，并配套了 9 例回归单测。

**卡点**：Windows 环境下 Python 管道输出受 GBK 编码干扰（改用 `PYTHONIOENCODING=utf-8` / 字节直通规避）；后台任务与前台端口竞争；WPS 验证曾因"打开瞬间白屏截图"误判为文件问题，最终以 WPS COM 渲染引擎导出 PNG 作为可靠 ground truth 替代屏幕截屏。

**与其他模块联动**：本模块是"S3 生成 → S4 版本"之间的枢纽——预览以版本快照（成员1 数据底座 + 版本体系）为数据源；事件循环修复解除了 Go 代理（backend/teacher）调 `gen/create` 的超时，与成员4 的管道稳定性任务交叉协作；intent 归一化修复了前端 S3StudioPage 原样透传 S1 意图导致的断链。真实 LLM 链路已验证可稳定出数，为全队联调与赛题演示提供了"生成→预览→持久化"的可靠底座。
