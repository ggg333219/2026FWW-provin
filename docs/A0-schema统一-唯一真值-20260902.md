## 4. 状态机统一核对

- **任务 status**（`GenerationTask.status`）：`pending → generating → [preview|modifying] → done|failed`。值集独立，语义=「生成任务」。Go 常量：`GenerationStatus*`（ai_engine_client.go，本次新增）。
- **阶段 stage**（`GenerationTask.stage`）：`intent_locked → evidence_gathering → structuring → generating → preview/modifying → done`。Go 常量：`GenerationStage*`。
- **导出 status**：`pending → exporting → done|failed`（导出是独立小状态机，不并入任务枚举）。Go 常量：`ExportStatus*`。
- **版本**：无进程状态，只有 `version_number` 递增 + `locked` 布尔；回滚=克隆新版本。
- **解析 ParseStatus**：`uploaded→parsing→chunked→indexed→done|failed`（S2 专用）。
- **意图会话 SessionStatus**：`collecting→clarifying→confirming→confirmed/locked`（S1 专用）。
- 约束：**各类状态枚举彼此不混用**；跨层引用时在 Go 用常量、在 Python 用 StrEnum，禁止裸字符串。任务 `error` 当前为纯文本（P1 再引入 `{code,message,retryable,details}`）。

## 5. 结构与真冲突复查

### 5.1 questions（P0 类型裁定）

- 线上 canonical：`node.questions` 与 `node.interactive_questions` 均为 **`list[str]`**（每题=问题文本）。写入侧（normalize_stage2/3、migrate_node、schema.py TeachingNode 注释、export_html5:121-126）已强制，**任何 dict 都会在此被压成字符串**。
- 真冲突：`export_html5` 判分 quiz 需要 dict（`question/options/answer/explanation`，78-94 行）。现有流：dict 若被塞进 `questions` 会在快照 pydantic 校验/归一化时丢成 str → quiz 降级为闪卡。
- **裁定**：结构化互动（可判分 quiz、flashcard）**不进 questions**，放 `node.metadata.interactive`（`[{type:"quiz",questions:[{question,options,answer,explanation}]},{type:"flashcard",front,back,tags}]`）；纯文本题才放 questions。`export_html5._node_to_items` 已消费 metadata.interactive（101-117 行），无需改导出。引擎各生成器如产 quiz dict，应写入 metadata.interactive（后续收口，见 P1）。

### 5.2 node

见 §1.2/§2。补充：`TeachingNode` 快照由 pydantic 校验，extra 顶层键（如历史 `interactive_items`）会被丢弃——**顶层键=白名单**；需要携带的扩展一律走 `metadata`。

### 5.3 evidence

Python `EvidencePacket` ⇄ Go `EvidencePacket` 已一致（chunk_id/source_ref/score…）。遗留：Go `SearchResultItem` 未含 `page_ref`，Python `Chunk` 含——RAG search 结果透传时 page 信息在 `source`/`metadata` 内，需时补字段（P1）。

### 5.4 export

引擎产物仅 3 类扩展名：`{job_id}.pptx / .docx / .html`（BOTH=pptx+docx+html 多文件，download_url 依序暴露一种）。Go 网关白名单已放开 `html`。lesson_plan 产物为 docx，download 复用 docx 下载。PDF 枚举存在但 `_run_export` 未实现产物——调用会得到 done 但无文件，UI 不应暴露 PDF 按钮（P1：要么实现要么下掉入口）。

### 5.5 Go 网关契约（smoke 暴露的两个裂缝，本次已修）

- **`omitempty` 丢空键**：引擎 Pydantic 序列化空值键仍在（`content:""`、`core_points:[]`），Go 镜像 `TeachingNodeItem` 若给 canonical 非 Optional 字段加 `omitempty`，网关解码再编码时会**把空键整体丢弃** → 前端/下游缺字段（smoke 抓到缺 5 个）。裁定：canonical 字段（content/summary/script/core_points/key_points/questions/interactive_questions/segments/source_chunk_ids/…）**禁加 omitempty**；只有 Optional（page_ref/next_node_id/排版提示/…）可留。
- **`nodes:null` → 引擎 422**：`GenerationPreviewRequest.Nodes` 不带 omitempty 时，仅传 `gen_id` 做快照预览的请求会编码成 `"nodes":null`，引擎 `PreviewRequest.nodes: list[dict]=[]` 收到 null 直接 422 → 预览空。已加 `omitempty`（nil 时省略该键，引擎走默认空列表）。
- 同理教训：**Go 请求体里「缺省即默认」的字段一律 omitempty**，避免把零值/null 传给 Pydantic 严格类型。

## 7.2 本次修改记录（2026-09-28 · P4 局部修改后的单页重规划）

背景：`/api/v1/gen/modify` 是老师改单页真正走的那条路（`CommandParser` → `NodePatcher.apply` → `_handle_update` → `generate_single`）。此前它只回写 `script` / `segments` / `point_details`：老师把第 2 页正文重写了，幻灯片上的图示与大字结论还停在旧内容上。本次让这一页的表达决策跟着正文一起换。

- **合并函数迁址**：`_merge_script_into_node` 从 `main.py` 移到 `ai_engine/gen/node.py`，更名 `merge_script_into_node` —— `gen/patch.py` 也要用它，而 `patch.py` 不能反向 import `main`（循环）。语义同时从「字段白名单」改为「保护键黑名单」（`_SCRIPT_PROTECTED_KEYS`）。
  - 白名单在两个调用点必炸其一：`/gen/create` 的 dict 过 `normalize_stage3_scripts` 白名单，`/gen/modify` 的 dict 是模型原样返回、还带着 `mindmap_markdown` / `reteach_script` / `transition`（前端在读，见 §3 A6 的 `reteachScript` / `transitionText`）—— 白名单会把它们悄悄丢掉。
  - 黑名单在 create 路径上可证等价（白名单本就排除 `node_id`/`title`/`node_type`/`type`/`content`/`summary` 这六个），在 modify 路径上无损失。
- `ai_engine/gen/node.py`：新增 `merge_script_into_node` —— **只增不减**，`None` / `""` / `[]` / `{}` 一律不覆盖。
  - 这条是「改完之后预览里的分段区块整个消失」的根因：`generate_single` 恒返回全键，模型这次没给分段就是 `segments: []`，`{**node, **script_data}` 会把该页已有分段清空。
- `ai_engine/gen/patch.py`：`_handle_update` 的 `{**node, **new_node}` 改为 `merge_script_into_node`。原写法还会冲掉 `type` / `node_type` / `key_points` / `summary` / `figure` / `teaching_plan` —— 幻灯片当场退化成「没有要点、没有图示」。
- `ai_engine/main.py`：
  - `_attach_teaching_plan(node, plan, *, replace=False)` 增加替换语义。`replace=True`（局部修改）时，重规划说这页不该出图 / 不该有结论就真的 `pop` 掉 —— 否则幻灯片上留着一张与新正文对不上的图，比没有图更糟。默认 `False` 是新建路径的语义（节点本来是干净的，只挂不删）。
    - 两个路径共用同一退化策略：**plan 为空 dict 时一律保留原有规划**。拿不到新决策不等于旧决策错了。
  - 新增 `_plan_node_safe`（单页规划，任何异常退回 `{}`）与 `_modify_target_ids`（`page_id` 优先，否则取命令里带 `node_id` 的命令）—— 证据回填与单页重规划按同一份集合取数。
  - `modify_nodes` 新增「Stage 局部重规划」：只对目标页调 `plan_node` + `_attach_teaching_plan(replace=True)`，**其他页一字未动**是这条路径的契约。
    - 用 `plan_node` 而非 `plan_deck`：逐页决策是这一页的事，且**不走**整份课件的出图配额（`MAX_FIGURE_PAGE_RATIO = 0.6`）。已知取舍：单页重规划可让整份课件的出图占比略微越过 0.6 —— 老师正在改这一页，它出图是对这次编辑的回应，不是「每页都硬塞一张图」。
- **教学意图随快照落盘**（P4 的取数地基，engine-internal，无 Go 镜像需要同步）：
  - `/gen/create` 的 `save_snapshot(metadata=...)` 增加 `"intent": req.intent.model_dump()`（原有 `outline_id` / `outline_version` 保留）。
  - `modify_nodes` 读回：版本快照分支 / 内容任务分支各取 `metadata["intent"]`；`nodes` 为内联提交时补读最新版本（不补读会把教学意图连同 `outline_id` 一起抹成 `{}`，改第二次就再也查不到）。
  - modify 的 `save_snapshot(metadata=snapshot_metadata)` 原样带过去 —— **`metadata` 不写进 meta 索引**（`gen/version.py:259` vs `:264` 之后的索引写入），只存在于 `v_N.json`，所以必须逐版本显式传递。
- 校验：`ai_engine/tests/test_modify_replan.py`（合并尺度 / 替换语义 / 意图透传 / 只改目标页 / 规划失败不毁页）+ `test_generation_pipeline_plan.py::test_create_writes_the_intent_into_the_snapshot`（create 侧写入）。
