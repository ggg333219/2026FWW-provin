## 三、代码修改清单（均在 `ai_engine/parse/video_processor.py`，最小改动）

实测发现的核心问题：**imageio-ffmpeg 只带 ffmpeg 不带 ffprobe，而原代码 4 处硬编码依赖 PATH 中的 `ffmpeg`/`ffprobe`，导致本机上抽帧静默返回空、时长取不到。** 修复：

| # | 修改 | 说明 |
|---|------|------|
| 1 | 新增模块级函数 `_resolve_tool(name)` | 工具路径解析：先查 PATH，`ffmpeg` 找不到时回退 imageio-ffmpeg 二进制；`ffprobe` 找不到返回 None 由调用方降级 |
| 2 | `_get_video_duration` 改为三级回退 | ffprobe → 解析 `ffmpeg -i` stderr 的 `Duration:` 行 → 纯 Python 解析 MP4 moov/mvhd atom（复用已有 `_parse_mp4_duration`）。原实现在无 ffprobe 时直接返回 0.0，导致抽帧被跳过 |
| 3 | `_get_metadata` 使用 `_resolve_tool("ffprobe")` | 无 ffprobe 时走纯 Python 时长解析；并新增用 `ffmpeg -i` stderr 解析分辨率（1280x720 实测成功），替代原来的 `NonexNone` |
| 4 | `_extract_keyframes` 使用 `_resolve_tool("ffmpeg")` | 替换硬编码 `["ffmpeg", ...]` |
| 5 | `__init__` whisper 模型解析优先级 | 显式参数 > `AI_WHISPER_MODEL` 环境变量 > 项目内置目录 `ai_engine/data/models/faster-whisper-base` > `"base"`（联网下载）。**离线优先**，避免演示机现场拉模型失败 |
| 6 | `_transcribe_with_faster_whisper` 异常落日志 | 原来 `except Exception: return []` 静默吞错（曾隐藏 IncompleteSnapshotError），现 warning 级落日志后仍走降级 |
| 7 | `.gitignore` 追加 `scripts/tmp_testvideo/` | 测试素材（视频/音频/帧）不入库；`ai_engine/data/` 原有条目已覆盖模型目录 |

未改动：`router.py`、`task_manager.py`（实测无需修改）。

## 五、给演示人员的一页操作指引

**前提**：本机已完成下列一次性配置（均已就绪，无需重做）：faster-whisper 与 imageio-ffmpeg 已安装；whisper base 模型在 `ai_engine/data/models/faster-whisper-base/`。

### 方式一：HTTP 接口演示（推荐，与 Go 后端契约一致）

```bash
cd D:/Desktop/2026FWW-provin
# 1. 启动 AI Engine（注意从项目根目录要写 ai_engine.main:app，不要写 main:app，
#    项目根的 main.py 是另一个遗留服务"文档解析服务"）
python -m uvicorn ai_engine.main:app --port 8000

# 2. 发起视频解析（PowerShell 或 curl，file_path 换成实际视频绝对路径）
curl -X POST http://127.0.0.1:8000/api/v1/parse/video \
  -H "Content-Type: application/json" \
  -d '{"session_id": "demo", "file_path": "D:/path/to/video.mp4", "language": "zh"}'
# => {"task_id": "parse_xxx", "status": "processing", "assets": [...]}

# 3. 轮询结果（首次调用需加载模型，约 10-30 秒）
curl http://127.0.0.1:8000/api/v1/parse/status/parse_xxx
# => status=done, chunks=[meta, frame×N, transcript]
```

也可用现成测试视频：`scripts/tmp_testvideo/test_video.mp4`（25 秒快速排序教学片段）。

### 方式二：前端教师端上传 mp4

教师端上传 mp4 → Go 后端转发 `POST /api/v1/parse/video` → 同上轮询，前端 SSE 可用 `POST /api/v1/parse/stream-process`（视频会按 meta → 帧 → 转写逐段推送）。

### 演示话术要点

1. **元信息**：无需 ffprobe 也能读出时长、大小、分辨率（纯 Python + ffmpeg 双通道）。
2. **关键帧**：ffmpeg 均匀抽 5 帧，带时间戳，可配 VLM 生成画面描述（未配 VLM 时显示降级占位，不报错）。
3. **语音转写**：本地 faster-whisper 离线推理，输出带 [秒] 时间戳的字幕段，后续可接 LLM 纠错修同音字。
4. **结构化**：所有产出标准化为 Chunk（含 chunk_id / source_type / 时间戳 metadata），直接进入知识库 RAG 管线。

### 故障速查

| 现象 | 原因 / 处置 |
|------|------------|
| transcript 是 "[ASR 语音识别不可用]" | 模型目录缺失。设 `AI_WHISPER_MODEL` 指向本地模型目录，或恢复 `ai_engine/data/models/faster-whisper-base/` |
| 抽帧 0 帧 | ffmpeg 不可达。确认 `pip install imageio-ffmpeg` 或 ffmpeg 在 PATH |
| 帧描述是"(降级占位)…" | 未配 VLM，属预期降级，不影响链路 |
| 访问 /docs 显示"文档解析服务" | 起服务时写成了 `main:app`，应写 `ai_engine.main:app`（或 cd ai_engine 目录再起） |
| 转写有同音字错误 | 预期行为，LLM 纠错环节（额度恢复后）会自动修正 |
