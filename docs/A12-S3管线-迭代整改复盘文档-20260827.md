### 1.3 P0 / P1 / P2 分级缺陷清单

#### P0 级致命问题（阻断主线，必须立即修复）

**P0-1：`questions` 字段类型冲突**

- **位置**：`ai_engine/core/schema.py` TeachingNode.questions 定义为 `list[dict[str, Any]]`（字典列表）
- **冲突方**：`normalize_stage2_nodes`、`normalize_stage3_scripts`、`_normalize_enhanced_scripts` 三处写出的为 `list[str]`（字符串列表）
- **影响**：前端预览渲染器 `_slide_quiz` 执行 `for q in questions` 时对字典迭代，会渲染出 Python 对象字符串而非问题文本，导致页面展示崩坏
- **根因**：成员1定义字段类型时未与渲染器读取方协商一致
- **修复方案**：将 `TeachingNode.questions` 类型改为 `list[str]`，与渲染器期望一致

**P0-2：`normalize_stage2_nodes` 双写逻辑被两任成员重复修改，存在歧义**

- **位置**：`ai_engine/schema.py`
- **根因**：成员1（e590c72）首次改写了该函数，成员4（7a7783c）基于更早版本再次改写，当前 main 分支实际采用的是成员4版本，但填充字段数量更多更完整；成员1的首次改写中部分字段未覆盖（如 `interactive_questions`）
- **影响**：维护歧义，后续开发不清楚哪套逻辑是"标准"；如成员1的 patch.py 依赖的 normalize 结果与成员4修改后的版本行为可能不一致
- **修复方案**：以成员4版本为基准，补充成员1版本中有但成员4版本中遗漏的字段（如 `interactive_questions` 双向映射），输出唯一标准版本

#### P1 级缺陷（影响功能完整性，需联调修复）

**P1-1：预览持久化后端接口缺失**

- **位置**：main.py 无 `GET /api/v1/gen/preview/{gen_id}` 路由
- **影响**：前端 preview 刷新后无法从后端恢复历史版本，localStorage 兜底仅覆盖本次会话，重启浏览器/切换设备后预览历史丢失
- **修复方案**：新增路由，读取 `data/versions/{gen_id}/v_N.json` 版本快照文件并调用 PreviewRenderer 渲染

**P1-2：segments 元数据在预览侧未语义化渲染**

- **位置**：`ai_engine/gen/preview.py` `_slide_content` 仅追加 `"── 讲授分段 ──"` 纯文本
- **影响**：segment_type、estimated_seconds、difficulty、interaction_hint 等元数据全部被忽略，分段教学信息不可见
- **修复方案**：在 `_slide_content` 中增加语义化分段展示（分段类型标签 + 时长 + 难度提示）

**P1-3：MinIO bucket 预检缺失导致静默失败回退**

- **位置**：`ai_engine/main.py` `_run_export` 调用 `minio_client.upload_file()`
- **影响**：生产环境首次部署时若 bucket 未提前手动创建，上传静默失败并回退本地路径，前端收到 `minio_path` 为本地路径而非 `minio://` URL
- **修复方案**：上传前增加 `bucket_exists()` 检查，不存在时调用 `make_bucket()` 自动创建

**P1-4：WPS 兼容性未实际验证**

- **位置**：`ai_engine/gen/templates/` 三套 PPTX 模板
- **影响**：承诺 Office/WPS 双端兼容，但仅验证了 python-pptx 文件结构有效性，中文排版、WPS 特性兼容存在未知风险
- **修复方案**：需在 WPS 实际环境中打开验证，补充截图证明

**P1-5：`two_column` 类型未实现双栏排版**

- **位置**：`ai_engine/gen/export_ppt.py` `_TYPE_ALIASES` 中 `"two_column": "content"` 直接收敛
- **影响**：双栏布局节点以普通内容页渲染，排版与设计意图不符
- **修复方案**：在模板和导出器中增加双栏版式支持

```python
@app.get("/api/v1/gen/preview/{gen_id}")
async def get_preview(gen_id: str, version: Optional[int] = None):
    """
    GET /api/v1/gen/preview/{gen_id} — 读取版本快照并渲染预览 HTML。
    
    version: 留空则加载最新版；指定版本号则加载指定版本快照。
    前端刷新页面时调用此接口恢复预览内容。

    # 1. 从 vm.load_version(gen_id, version) 获取节点数组
    # 2. 若内存 dict _gen_tasks 中已有最新数据且 version=None，直接用内存版本
    # 3. 若无，从 data/versions/{gen_id}/v_N.json 读取
    # 4. 调用 PreviewRenderer().render(nodes) 生成 HTML
    # 5. 返回 { "html": html_str, "version": v_no, "node_count": len(nodes) }
```

**关键约束**：
- 路由路径为 `/api/v1/gen/preview/{gen_id}`，不对应任何现有 Go 接口，保持 Python FastAPI 独立运行
- 返回结构：`{ html: string, version: int, node_count: int }`
- 版本快照文件不存在时返回 404，前端兜底显示空状态
- 读取快照后节点数据直接传入 PreviewRenderer，不做额外转换

#### P1-2（必须完成）：segments 元数据语义化渲染

修改 `ai_engine/gen/preview.py` 中 `_slide_content` 方法，在追加 segments 内容时展示完整元数据：

当前逻辑（需改进）：

if segments:

改造为语义化展示：

if segments:

    for seg in segments:

        seg_label = _SEGMENT_TYPE_LABELS.get(seg_type, seg_type)

        body += f'<span class="seg-diff">{seg_diff}</span>'
        body += f'<p class="seg-text">{html.escape(seg_text[:100])}</p>'

#### P2-3（必须完成）：分布式锁指数退避重试

修改 `ai_engine/gen/version.py` 中 `_RedisLock.acquire()` 方法，增加指数退避重试：

```python
def acquire(self, max_retries: int = 3) -> bool:
    """尝试获取 Redis 分布式锁，失败时指数退避重试。"""
    import time
    client = _get_redis_client()
    if client is None:
        return False
    import uuid
    token = str(uuid.uuid4())
    delay = 0.1  # 100ms 初始延迟
    for attempt in range(max_retries):
        try:
            ok = client.set(self.key, token, nx=True, ex=self.ttl)
            if ok:
                self._token = token
                return True
        except Exception:
            pass
        if attempt < max_retries - 1:
            time.sleep(delay)
            delay *= 2  # 指数退避：100ms → 200ms → 400ms
    return False
```

同时更新 `_DistributedLock.__enter__` 调用：`self._rlock.acquire(max_retries=3)`。

#### P2-1（附加优化）：validator 分页语义连贯性

修改 `ai_engine/gen/validator.py` 中 `_paginate_by_paragraphs`，优先在段落边界（`\n\n`）切分：

```python
def _paginate_by_paragraphs(self, node: dict, paragraphs: list, title_base: str, page_count: int) -> list[PaginatedNode]:
    """按段落拆分，优先保证段首段尾语义完整。"""
    import math
    # 先按段落边界分配，尽量不在段落中间切分
    paras_per_page = math.ceil(len(paragraphs) / page_count)
    pages: list[PaginatedNode] = []
    for pg in range(page_count):
        start = pg * paras_per_page
        end = start + paras_per_page
        page_paras = paragraphs[start:end]
        if not page_paras:
            continue
        content = "\n\n".join(str(p).strip() for p in page_paras if str(p).strip())
        title_suffix = f"（{pg + 1}/{page_count}）" if page_count > 1 else ""
        pages.append(PaginatedNode(
            index=pg + 1,
            total=page_count,
            title=f"{title_base}{title_suffix}",
            content=content,
            key_points=[],
            segments=[],
            node_type=str(node.get("type") or node.get("node_type") or "content"),
            layout_hint=node.get("layout_hint"),
            font_size_hint=node.get("font_size_hint"),
        ))
    return pages
```

关键：只有当 `len(paragraphs) < page_count`（段落数不足以填满每页）时，才允许段落内按字数均分，避免单句话被截断至两页。
