# 项目启动命令

本文档汇总「教师端 + S2 资料解析真实链路」的启动命令。

> ⚠️ 关键区别：教师端前端走的是 **`cmd/teacher` 后端（端口 8082）**，不是旧的 `api/main.go`（端口 18080）。
> 二者不是一回事：`cmd/teacher` 才注册了 `/api/v1/parse/*`、`/api/v1/gen/*`、`/api/v1/version/*` 等
> 资料解析与课件生成路由；`api/main.go` 是通用 OpenAPI 后端，教师端前端并不直接调用它。

---

## 前置条件

- Docker Desktop 已启动
- Go、Node.js、npm 已安装
- Python 环境（推荐 conda，环境名 `fuww_ai`）

---

## 1. 启动基础服务（PostgreSQL / Redis / MinIO）

教师端后端（`cmd/teacher`）通过 `backend/.env.local` + `backend/config/config.local.yaml`
连接到 **测试端口映射**（25432 / 26379 / 29000），因此必须用**测试 compose 文件**启动：

```bash
docker compose --env-file .env.test -f docker-compose.test.yml up -d postgres redis minio minio-init
```

验证容器就绪：

```bash
docker ps --filter "name=teaching-test" --format "{{.Names}}\t{{.Status}}"
# 应看到 teaching-test-postgres (25432)、teaching-test-redis (26379)、teaching-test-minio (29000/29001)
```

> ⚠️ 不要用 `backend/docker-compose.yml` + 根目录 `.env`：那套映射的是 5432 / 6379 / 9000，
> 而教师端后端连的是测试端口 25432 / 26379 / 29000，端口对不上会导致后端回退到
> `runS1Standalone`（只保留对话/知识点，**没有 parse 路由**，切片会一直是 0）。

## 2. 启动 AI 引擎（Python FastAPI）

```bash
cd ai_engine
conda activate fuww_ai   # 或你自己的虚拟环境
python main.py
```

AI 引擎健康检查：http://localhost:8000/health → 返回 200

## 3. 启动教师端后端（Go）

```bash
cd backend
go run ./cmd/teacher
```

教师端后端健康检查：http://localhost:8082/api/health → 返回 `{"code":200,"data":{"status":"UP"}}`

> ⚠️ 健康检查路径是 **`/api/health`**，不是 `/health`（`/health` 返回 404）。
> 前端探测的也是 `/health` 和 `/api/health`，只要 `/api/health` 通了，前端就不会进入 mock 模式。

启动成功后，日志里应能看到这些**真实解析路由**（能看见才算没掉进 S1-standalone 回退）：

```
POST /api/v1/parse/upload
POST /api/v1/parse/process
GET  /api/v1/parse/status/:task_id
POST /api/v1/parse/video
```

## 4. 启动前端（Vue 教师端）

```bash
cd frontend/teacher
npm install   # 首次运行需要
npm run dev
```

前端地址：http://localhost:5173

> 前端 API 基址由 `frontend/teacher/.env.local` 决定，内容应为：
>
> ```
> VITE_API_BASE=http://localhost:8082
> VITE_AI_API_BASE=http://localhost:8000
> ```
>
> 如果 `.env.local` 不存在，会退回 `.env.example` 的 `http://localhost:18080`（旧后端，教师端不适用），
> 需要手动创建 `.env.local` 指到 8082。

## 服务地址汇总（教师端真实链路）

| 服务 | 地址 | 健康检查 |
|------|------|----------|
| 教师端后端 | http://localhost:8082 | `/api/health` |
| AI 引擎 | http://localhost:8000 | `/health` |
| 教师端前端 | http://localhost:5173 | — |
| PostgreSQL（测试） | localhost:25432 | — |
| Redis（测试） | localhost:26379 | — |
| MinIO API（测试） | localhost:29000 | — |
| MinIO 控制台（测试） | localhost:29001 | — |

## 一键启动（推荐）

仓库自带脚本 `scripts/start-all.ps1`，可一键拉起 AI 引擎、教师端后端、前后端：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-all.ps1
```

停止：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop-all.ps1
```

> ⚠️ `start-all.ps1` 的 Docker 步骤默认用 `backend/docker-compose.yml`（5432/6379/9000），
> 与教师端后端所需的测试端口（25432/26379/29000）不一致。因此**用脚本前，请先手动执行第 1 步**
> 把测试容器拉起来，否则后端会因连不上库而回退到 S1-standalone。

---

## 快速重启

```bash
# 重启基础服务
docker compose --env-file .env.test -f docker-compose.test.yml restart postgres redis minio

# 重启 AI 引擎（前台 Ctrl+C 终止后重新运行）
cd ai_engine && conda activate fuww_ai && python main.py

# 重启教师端后端（前台 Ctrl+C 终止后重新运行）
cd backend && go run ./cmd/teacher

# 重启前端
cd frontend/teacher && npm run dev
```

## 注意事项（排查 S2 切片为 0）

1. **确认后端是 `cmd/teacher`（8082）且连上了测试库**：日志出现 `POST /api/v1/parse/upload` 等路由，
   且 `/api/health` 返回 200。若只看到对话/知识点路由、没有 parse 路由，说明后端回退到了
   `runS1Standalone`——检查测试容器（25432/26379/29000）是否就绪。

2. **清除前端的 mock 模式标记**：前端探测不到后端时会写入 `localStorage` 的 `fuww_mock_mode` 并走假数据，
   此时即使后端起来了也不会发真实解析请求。在浏览器 DevTools → Console 执行：
   ```js
   localStorage.removeItem('fuww_mock_mode')
   ```
   然后刷新页面。

3. **前端请求要看到真实的 parse 链路**：上传资料后，DevTools → Network 里应能看到
   `/api/v1/parse/upload` → `/api/v1/parse/process` → 轮询 `/api/v1/parse/status/:task_id` 三个请求。
   若完全没有 parse 请求，多半是 `VITE_API_BASE` 指错了端口（应指 8082）或仍处于 mock 模式。

4. **AI 引擎必须真实可用**：`http://localhost:8000/health` 返回 200。后端 `config.local.yaml` / `.env.local`
   的 `ai.base_url` 指向 `http://127.0.0.1:8000`，AI 引擎没起会导致切片流程停在解析阶段。
