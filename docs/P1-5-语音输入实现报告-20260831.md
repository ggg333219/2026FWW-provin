## 3. 方案设计

### 3.1 技术选型

- **浏览器原生 Web Speech API**：`window.SpeechRecognition || window.webkitSpeechRecognition`。Chrome / Edge 内置实现走 Google 语音服务，免费、无需 API Key，中文普通话识别质量满足课堂需求。
- **不引入第三方 SDK / 云服务**：赛题演示环境无额外密钥管理成本，且与项目「前端只做交互、AI 能力在后端」的架构不冲突——语音识别属于输入采集层（浏览器能力），结构化理解仍由 S1 意图理解完成。

### 3.2 交互选择：点击开始/停止（非按住说话）

选择**单击开始、再次单击停止**：

- Web Speech API 是事件驱动的长会话，按住说话在桌面端受鼠标移出、`mouseup` 丢失、按钮 focus 抢占 textarea 焦点等影响，交互不稳；
- 点击模式教师可腾出双手看讲稿阐述教学思路，符合 2a「阐述教学思路」的长句场景。

### 3.3 转写结果处理

- `continuous = true` + `interimResults = true`；
- **中间结果**（isFinal=false）只在按钮上方的实时预览气泡中展示，供教师确认识别方向，不写入输入框，避免反复回改；
- **最终片段**（isFinal=true）逐段通过 `transcript` 事件抛给父组件，`appendTranscript` 直接追加到 `draft`（中文场景无需空格连接），之后由教师手动 Enter 发送或继续补充——转写完全并入现有消息发送流程。

### 3.4 会话续开

Chrome 在静音约数秒后会自动触发 `onend` 结束会话。组件内部维护 `shouldListen` 标记：只要用户没有主动点击停止，`onend` 后延迟 250ms 自动 `start()` 续开，保证教师思考停顿时不会被切断。`no-speech` / `aborted` 视为正常静音，不报错。

### 3.5 降级与错误处理

| 场景 | 行为 |
|------|------|
| 浏览器不支持（Firefox/Safari 旧版等） | `isSupported=false`，按钮置灰禁用 + title 提示「当前浏览器不支持语音识别，请使用 Chrome / Edge」，不影响文字输入 |
| 麦克风权限被拒（`not-allowed` / `service-not-allowed`） | 停止录音，按钮上方弹出可关闭提示条：「请在浏览器地址栏允许麦克风权限后重试」，同时 emit `error` |
| 无麦克风设备（`audio-capture`） | 提示条「未检测到可用麦克风，请检查设备连接」 |
| 识别服务网络异常（`network`） | 提示条「语音识别服务网络异常，请检查网络后重试」 |
| 其他错误 | 提示条展示错误码并允许重试 |
| 组件卸载 | `onBeforeUnmount` 中 `abort()` 释放识别实例并清理重启定时器，避免内存泄漏与幽灵录音 |

注意：Web Speech API 要求 `https://` 或 `localhost` 才可用（浏览器安全策略），本地 `npm run dev`（localhost:5173）可直接测试。

## 4. 组件 API（VoiceInputButton.vue）

```js
// Props
{
  disabled: Boolean,   // 外部禁用（S1 页在 isAnalyzing / isConfirmed 时禁用），默认 false
  lang: String         // 识别语言，默认 'zh-CN'
}

// Emits
{
  transcript: (text: string) => void,        // 每个最终转写片段（已 trim，非空）
  error: (message: string) => void,          // 权限/设备/网络等错误信息
  state-change: (listening: boolean) => void // 点击切换录音状态时通知
}

// Expose
{ stop(): void, isSupported: boolean }
```

S1 页集成方式（`TeacherIntentPanel.vue`）：

```html
<VoiceInputButton
  :disabled="store.isAnalyzing || store.isConfirmed"
  @transcript="appendTranscript"
/>
```

```js
const appendTranscript = (text) => {
  if (!text) return
  draft.value = draft.value ? `${draft.value}${text}` : text
}
```

## 6. 浏览器兼容性

| 浏览器 | 支持情况 | 表现 |
|--------|---------|------|
| Chrome（桌面，含 Edge） | ✅ 完整支持 | 语音识别可用，走 Google 语音服务 |
| Edge（Chromium 内核） | ✅ 完整支持 | 同 Chrome |
| Firefox | ❌ 不支持 SpeechRecognition | 按钮置灰 + tooltip 降级 |
| Safari | ⚠️ 仅 `webkitSpeechRecognition` 且需 Safari 14.1+ / iOS 14.5+，实际可用性差 | 组件做了构造函数探测，缺失即降级 |
| 协议要求 | — | 仅 `https://` 或 `localhost` 可用，`http://` 非 localhost 环境会静默不可用（Chrome 会拒绝麦克风） |

备注：Web Speech API 的识别在 Chrome 中由远端服务完成，需联网；离线环境点击麦克风会触发 `network` 错误提示条。

## 7. 人工验证步骤（3 步）

本次未做真实浏览器自动化录音测试（headless 环境无麦克风），请按以下步骤人工验证：

1. **打开页面**：Chrome/Edge 访问 `http://localhost:5173`（`cd frontend/teacher && npm run dev`），登录后进入「S1 意图」页，确认输入框右下角「发送」按钮左侧出现麦克风图标按钮；
2. **语音转写**：点击麦克风按钮（按钮变红并有呼吸光圈，上方出现「正在聆听」气泡），对麦克风说「我想做一节关于排序算法的课」，观察气泡实时显示中间文字，片段说完后最终文本**自动追加进输入框**；
3. **入链路发送**：再次点击麦克风停止录音，按 Enter 发送，确认消息以正常教师消息气泡出现在对话流中，右侧意图画像正常更新。

补充验证（可选）：用 Firefox 打开确认按钮置灰且有 tooltip；拒绝浏览器麦克风权限后确认出现红色权限提示条。

## 8. 遗留问题与建议

1. **未做真实浏览器自动化测试**：语音识别依赖真实麦克风与远端服务，vitest 无法覆盖；已通过 build + 单测回归 + 第 7 节人工步骤兜底。后续可引入 Playwright + fake media stream（`--use-fake-device-for-media-stream`）做 E2E。
2. **识别结果为纯文本**：语音输入只是把口语转成文字填入输入框，标点/数字格式依赖 Chrome 识别质量；口语化长句的理解仍由 S1 意图结构化兜底（本轮实测链路不变）。
3. **网络依赖**：Chrome 的识别走远端服务，答辩现场需保证网络可达 Google 服务；如现场网络受限，可考虑后续替换为后端 Whisper 方案（AI Engine 已规划视频 ASR 能力，可复用），前端只需把 `transcript` 事件源换成 WebSocket 推流，组件 API 不变。
4. **S2/S3 页未集成**：本轮按赛题 2a 只覆盖 S1「教师阐述教学思路」主场景；`VoiceInputButton` 为独立组件，后续 S2/S3 输入区可直接复用。
