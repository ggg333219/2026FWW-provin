### 2.3 生成策略（导出永不空）

```
generate(nodes, intent, markdown=None)
  ├─ AI_GEN_MODE=mock ──────────────► 直接 fallback 构造样例（data_source="mock"）
  ├─ LLM chat_with_schema 成功 ─────► _plan_from_llm 规范化（data_source="llm"）
  │    └─ 缺 objectives/process 等硬性字段 → 视为失败
  └─ 任何异常（429/超时/坏 JSON/空结构）► _build_fallback_plan（data_source="fallback"）
```

Fallback 是确定性机械拼装：节点按类型映射到标准四阶段（title→导入、content/section→新授、quiz/interactive→练习、summary→小结），缺失阶段补模板行；三维目标、重点难点、教学方法、课堂活动、作业、板书全部从节点 title/core_points/questions + 意图字段生成，任何输入组合下结构完整。

## 3. 导出接入方式（选择说明）

**选择：新增 `lesson_plan` 导出格式，而非把 docx 导出升级为教案版式。**

理由：
1. 既有 `DOCExporter` 节点排版被 `ai_engine/gen/tests/`（test_all.py / test_export_task.py）与 `verify_export_upload.py` 依赖，改版式必然动回归基线；
2. 节点排版 DOCX 与标准教案是两种交付物（讲义 vs 教研文档），保留两者并存更符合赛题语义；
3. 最小侵入：`_run_export` 只加一个 `if fmt == ExportFormat.LESSON_PLAN` 分支，产物写入 `meta["doc_path"]`（.docx），**零改动**复用既有 MinIO 上传循环（key→ext 映射 docx）与 `GET /download/{job_id}.docx` 下载、`/api/v1/export/status` 的 download_url 逻辑；
4. Go 侧 `ai_engine_client.go` 的 Format 是透传 string，无需后端改动即可透传 `lesson_plan`。

调用方式：`POST /api/v1/export/{gen_id}` body `{"format": "lesson_plan"}`；意图摘要从内存 `_gen_tasks` 按 generation_id 回查（查不到时 fallback 仅靠节点，仍可导出）。导出任务 metadata 记录 `lesson_plan_source`（llm/fallback/mock）便于排查质量来源。

DOCX 版式（WPS 兼容红线：仅段落/表格/加粗/对齐基础特性；中文微软雅黑，ascii/hAnsi/eastAsia 三处同设）：

```
{课程名}教案（居中 16pt 加粗）
[基本信息表 2×4] 课程名称|v|学科|v / 授课对象|v|课时|v
一、教学目标        —— 三维目标编号列表
二、教学重点与难点  —— 重点/难点分组编号
三、教学方法        —— 顿号连接列表
四、教学过程        —— 5 列表格：阶段|教师活动|学生活动|设计意图|时长（分钟）
五、课堂活动设计    —— 编号列表
六、课后作业        —— 编号列表
七、板书设计        —— 可选（board_design 非空才输出）
```

## 5. 遗留问题

1. **真实 LLM 路径未实测**：当日额度 429，`data_source="llm"` 路径仅用 MockLLMClient 验证了契约（预设 JSON → 规范化一致）；待额度恢复后用真实课件跑一次端到端，确认 LLM 返回字段命名与 `_plan_from_llm` 的宽容度匹配；
2. **前端/Go 侧未接线**：`format="lesson_plan"` 已可从 AI Engine API 透传，但教师端导出按钮与 Go handler 的格式白名单尚未加该选项（Go 侧为 string 透传，不会报错，只是 UI 暂无入口）；
3. **`both` 格式不含教案**：为保住 verify_export_upload T8 的 3 件套断言（pptx/docx/html），`both` 行为未变；若答辩演示希望"一键导出配套教案"，后续可在 `both` 分支追加教案产物并把上传清单扩为 4 件（需同步更新 T8 断言）；
4. **fallback 时长分配是模板比例**（导入 10% / 新授 60% / 练习 20% / 小结 10%），LLM 路径下由模型按节点 estimated_duration 求和输出，更精确。
