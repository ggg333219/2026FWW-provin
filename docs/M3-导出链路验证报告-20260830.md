## 1. 审计结论：原导出是否真的上传 MinIO？

**结论：链路骨架存在，但实际从未真正上传成功过，且失败被静默吞掉。**

- `ai_engine/main.py` 的 `_run_export` 原本就调用了 `MinioClient.upload_file`（`ai_engine/parse/minio_client.py`）。
- 但该 `upload_file` 在异常时 **吞掉所有异常并静默返回本地路径**（原 `minio_client.py` 第 144-150 行的 `except Exception: return local_path`），调用方无法区分"已上传"与"未上传"。
- 更关键的事实：**`minio` Python 包在本机未安装**（`python -c "import minio"` 报 `ModuleNotFoundError`）。`MinioClient._get_client` 内部延迟导入 minio 失败 → 异常被 `upload_file` 吞掉 → 返回本地路径。因此此前实测生成的 31KB 文件，`job.minio_path` 实际是**本地路径**，从未产生 `minio://` URL。
- 其他问题：
  1. `ExportFormat.BOTH` 时原代码用 `if/elif`，**DOCX 文件从不上传**；
  2. 上传失败不记录 `upload_status`，`ExportStatusResponse` 也无该字段，Go/前端无法感知降级；
  3. `MinioClient` 忽略 `MINIO_USE_SSL` 配置。

## 2. 本次改动

### M3-2A MinIO 真实上传链路

| 文件 | 改动 |
|------|------|
| `ai_engine/gen/export_upload.py`（新增） | 独立上传辅助：显式区分 `uploaded / failed / skipped` 三态；bucket 预检（不存在自动 `make_bucket`）；minio 包延迟导入+友好提示；任何失败返回结构化结果不抛异常；配置沿用 .env 现有命名 `MINIO_ENDPOINT / MINIO_ACCESS_KEY / MINIO_SECRET_KEY / MINIO_BUCKET / MINIO_USE_SSL`（未改 .env） |
| `ai_engine/main.py`（仅导出段） | `_run_export` 改用新模块；修复 BOTH 只上传一个文件的问题；上传段独立 try/except（上传任何异常都不会把已 DONE 的导出翻转为 FAILED）；`job.metadata` 记录 `upload_status / upload_error / uploads[]`；移除已无引用的 `MinioClient` 导入 |
| `ai_engine/core/schema.py` | `ExportStatusResponse` 增加只增不删的可选字段：`upload_status / minio_path / file_size`（符合项目"字段只增不删"接口规则） |
| `ai_engine/requirements.txt` | 启用 `minio>=7.2.0` 依赖（原来在注释里） |

**降级契约**：导出成功 → 上传失败时任务状态仍为 `done`，本地文件路径保留（`/download/{job_id}.pptx` 下载链路不中断），响应中 `upload_status=failed`（minio 包未装则为 `skipped`）并附原因。

### M3-2B PPTX 模板美化 + WPS 兼容（`ai_engine/gen/export_ppt.py`）

1. **东亚字体补丁（对 WPS 影响最大）**：python-pptx 的 `font.name` 只写 `a:latin`（西文字形），WPS/中文 Office 渲染中文读的是 `a:ea` 字形，缺失会回退默认宋体。新增 `_apply_ea_font()`，在所有文本框/面板段落与 run 上写入 `<a:ea typeface="微软雅黑"/>`。西文 latin 字形保持主题原有 `Microsoft YaHei`（即微软雅黑的英文名）。
2. **quiz 题目排版增强**：旧代码对 dict 题目直接 `str(q)`，会把 Python 字典字面量印到幻灯片上。现在兼容 `{question, options, answer}` 结构：题干加粗、选项按 `A．B．C．D．` 排版、附"参考答案：X"（secondary 色）；带选项题每页 2 题、纯题目每页 5 题，混排时按占位大的算，防溢出；跨页编号连续。
3. **既有版式保持**：封面（primary 深蓝底 + 大标题 + accent 侧条）/章节页/内容页（kicker + 标题 + 分隔线 + 双栏面板）/摘要页层级结构沿用，配色为 default 主题统一教学色板（深蓝 `245B78` + 深灰蓝正文 `183042` + 橙 accent `E89B52`）。
4. **WPS 兼容红线自查**：仅用文本框、简单形状（矩形/圆角矩形/圆）、字号、颜色、加粗；无 SmartArt、无母版水印、无外部图片、无图表（验证脚本 A5 断言通过）。

## 5. 遗留问题

1. **真实 MinIO 端到端未验证**：本机无 MinIO 服务。部署环境启动 MinIO 后，设置 `.env` 中 `MINIO_*`（已有，bucket=teaching）并 `pip install -r ai_engine/requirements.txt`，再跑一次导出即可确认 `minio://teaching/exports/...`。
2. **`parse/minio_client.py` 的静默回退仍在**：S2 解析等其他模块仍使用旧的 `MinioClient`（上传失败静默返回本地路径）。本次按边界只改导出链路，建议后续统一迁移到 `export_upload.py` 的显式三态模式（涉及 parse 路由，超出本次授权范围）。
3. **`download_url` 仍为本地相对路径**：`/download/{job_id}.pptx` 依赖 AI Engine 进程内存活（`_export_tasks` 是进程内字典，重启即失）。生产化需要把导出任务落库或由 Go 端生成 MinIO 预签名 URL，属跨端改动，需与后端成员对齐。
4. **DOCX 导出模板未在本次范围内美化**（任务限定 PPTX），如需同步补 ea 字体可复用 `_apply_ea_font` 思路。
