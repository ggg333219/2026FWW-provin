### A5. 新增会话管理模块（S1 意图理解的后端部分）

**操作**：

```go
// POST /api/v1/conversations          — 创建会话
// POST /api/v1/conversations/:id/messages — 发送消息
// POST /api/v1/conversations/:id/confirm  — 确认意图
// GET  /api/v1/conversations/:id      — 获取会话状态
```

在 `backend/internal/service/` 新建 `conversation_service.go`：

```
核心方法 ProcessMessage():
  1. 加载或创建 DialogueSession
  2. 追加教师消息轮次
  3. 若已锁定（confirmed → locked）则拒绝修改
  4. 调用同学 B 的 intent/extract 接口（Python）
  5. 根据响应更新会话状态机
  6. 追加智能体回复轮次
  7. 返回响应 + 追问列表
```

**会话状态机**：

```
collecting → clarifying → confirming → confirmed → locked
     ↑           ↑                          ↓
     └───────────┴── 教师发新消息可回到 collecting
```

**复用现有代码**：
- `DialogueSession` 模型在 `backend/internal/service/models.go` lines 110-120（加 `status` 字段）
- `DialogueTurn` 模型 lines 208-222（加 `turn_type` 字段）
- `ensureDialogueSession()` 模板在 `dialogue_support.go` lines 17-54
- `appendDialogueTurn()` 模板在 `dialogue_support.go` lines 63-83

**DB 迁移**：
- `dialogue_sessions` 表：添加 `status VARCHAR(30) DEFAULT 'collecting'`、`intent_summary JSONB`
- `dialogue_turns` 表：添加 `turn_type VARCHAR(20) DEFAULT 'initial'`

**完成标志**：可 POST 消息获得结构化响应，状态机流转正确。

### A7. 新增导出模块（S4 个性化满足）

**目标**：异步导出课件为 PPTX/DOCX，存储到 MinIO。

**操作**：

在 `backend/internal/service/` 新建 `export_service.go`：

```
// CreateExportJob(genID, format) → ExportJob (异步)
// GetExportStatus(jobID) → ExportJob
// GetDownloadURL(jobID) → string
```

**数据模型**：
```go
type ExportJob struct {
    ID         string    `gorm:"primaryKey"`
    GenID      string    `gorm:"index"`
    Format     string    // "pptx" | "docx" | "both"
    Status     string    // "pending" | "exporting" | "done" | "failed"
    MinioPath  string
    CreatedAt  time.Time
}
```

**处理模式**：
1. 前端请求导出 → 创建 ExportJob（status=pending）
2. 返回 task_id → 异步通知同学 B 的 gen/export 接口
3. 同学 B 完成 → 回调或前端轮询状态
4. 状态 done → 返回 MinIO 下载 URL

**路由**：
```
POST /api/v1/exports/:gen_id        — 创建导出任务
GET  /api/v1/exports/status/:job_id — 查询状态
```

**完成标志**：可发起导出、查询进度、获得下载 URL。
