# S4 修改指令问题

## 问题：自然语言修改指令无法理解（P0）

### 现象

赛题要求"老师提出修改需求（如'这里加一个游戏设计'），系统生成新 PPT"，但当前系统：

- `CommandParser._parse_natural_language` 的正则规则只支持极少数固定句式
- 几乎所有自然语言反馈都落入兜底处理（`update_node` + `raw_feedback=True`），没有实际执行
- 前端 UI 只能选结构化操作（下拉框），老师无法直接输入自然语言

### 示例失效场景

| 用户输入 | 期望行为 | 实际行为 |
|---------|---------|---------|
| "这里加一个游戏设计" | 在当前位置插入新节点"游戏设计" | 不匹配任何规则，落入兜底 update_node，内容被忽略 |
| "把第三页标题改一下" | 修改第三页标题 | node_id "第三页标题" 不存在，报节点不存在错误 |
| "把导入和总结换个位置" | 交换两个节点 | "导入"和"总结"不是有效 node_id |
| "这一页太长了，拆成两页" | 拆分为两个节点 | 不匹配 split_node 规则 |

### 根因分析

#### 1. 自然语言解析能力极弱

```python
# ai_engine/gen/commands.py:93-127
def _parse_natural_language(self, text: str) -> ParseResult:
    rules = [
        # 必须完整匹配以下格式，缺一不可
        (r"(?:把|将|给)(\S+?)(?:改为|改成|...)(\S+)", UPDATE_NODE),
        (r"(?:在|于)(\S+?)(?:后|前)(?:添加|插入|...)(\S+)", ADD_NODE),
        # ...
    ]
    # 不匹配 → 兜底 update_node + raw_feedback
```

#### 2. node_id 体系与老师认知不匹配

老师的认知是"第三页"、"导入部分"、"总结"，
系统内部是 `node_001`、`node_002`。

没有任何将老师语言中的上下文引用映射到具体 node_id 的机制。

#### 3. 前端 UI 无自然语言入口

S4VersionPage 的修改指令面板只有结构化下拉框（`update_node / add_node / delete_node`），
没有自然语言输入框。

### 修复方案

#### 方案 A：增加 LLM 路由层（快，推荐）

在 `gen/modify` 端点前增加一个 LLM 判断步骤：

```python
# 新增端点或修改现有 gen/modify
@app.post("/api/v1/gen/modify")
async def modify_nodes(req: ModifyRequest):
    # 如果 commands[0] 是自然语言，调用 LLM 转换
    if req.commands and isinstance(req.commands[0], str):
        # 调用 LLM 将自然语言转换为结构化命令
        llm_result = await call_llm_convert(req.commands[0], context_nodes)
        if llm_result.structured:
            req.commands = [llm_result.commands]
        else:
            return {"status": "llm_reject", "reason": llm_result.reason}
    
    # 后续流程不变
    ...
```

#### 方案 B：重写 _parse_natural_language（慢）

支持更多自然语言模式 + 上下文推断 + 节点标题模糊匹配：

```python

    # 2. 意图分类：新增/删除/修改/交换

```

**推荐方案 A**——利用 LLM 本身理解自然语言的能力，在结构化命令之前加一层 NL→命令转换，成本最低，效果最好。
