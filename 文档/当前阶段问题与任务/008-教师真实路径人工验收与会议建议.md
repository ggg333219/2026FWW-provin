> 验收日期：2026-08-21
> 验收代码：`main@66133aa`
> 验收角色：教师 `manual_qa`

## 一、结论先行

负责人反馈属实，而且当前问题比“课件内容不够好”更靠前：**教师主路径没有形成一个连续产品**。

目前真实路径是：

```text
首页找不到创建入口
  → 知道直链后进入 S1
  → S1 丢字段并污染知识点
  → S2 可进入，但可生成空证据包
  → “进入 S3”落到旧讲稿编辑器
  → 只能给预置课件生成一段泛化讲稿
  → S4 要求教师手填 Generation ID
  → 即使人工取得 ID，版本、修改、导出 UI 仍因接口契约错误不可用
```

绕过前端直接调用完整生成和导出接口，确实能得到一个 `.pptx` 文件，但只有 4 页：封面加“核心概念 / 关键应用 / 总结过渡”三页。内容页为纯白底黑字和一句通用描述，不包含快速排序、45 分钟设计、动画、小游戏、证据引用或高级视觉设计。**“文件扩展名是 PPTX”不等于“生成了可交付课件”。**

本轮建议不要继续分散修细节，先以一条可演示的黄金路径为唯一 P0：

> 从首页点击新建 → S1 确认 → S2 可选资料 → S3 生成可预览 PPT → 教师用自然语言修改 → 产生 v2 → 导出新 PPTX，整个过程不要求教师输入任何内部 ID。

## 二、人工验收记录

### 2.1 S1：意图理解

教师首轮输入：

> 我想给大一学生做一节关于快速排序的课，讲课时间45，风格活泼一点，最好有动画演示和课堂小游戏。

实际结果：

- 正确提取主题“快速排序”。
- 未识别“45”为授课时长，继续追问时长；补充“45分钟”后才识别。
- 未提取“大一学生”为授课对象。
- 未提取“活泼”为教学风格。
- 未把动画演示和课堂小游戏写入互动要求。
- 反而把“一节关于快速排序的课”“风格活泼一点”列为核心知识点。
- 在画像仅 70% 时即可锁定，缺失和误提取字段直接进入下游，没有字段级人工纠错。

判断：S1 不是单纯“多问一轮”，而是会生成错误结构化输入，后续课件再强也会从错误需求出发。

### 2.2 S2：资料与证据

实际结果：

- 检索词能自动预填“快速排序”，说明主题透传成功。
- 页面直接出现与本次会话无关的旧素材“要求”“第4-2章 组合逻辑电路-陈信”，存在上下文污染和数据隔离风险。
- “快速排序”检索 0 命中时仍能点击“生成证据包”，并提示成功。
- 生成结果为 `0 chunks · 0 引用`、合成上下文为空，但没有阻断后续生成，也没有提示将退化为无证据生成。
- 顶部 S3 链接进入 `/courseware/create/s3-studio`，底部“进入 S3 生成”却进入 `/workspace`，同一步骤存在两套入口。

判断：S2 目前更像独立技术演示页，尚未成为可靠的“资料选择与生成依据确认”步骤。

### 2.3 S3：课件生成

#### 页面路径

- `/courseware/create/s3-studio` 的标题就是“S3 讲稿生成”。
- 页面要求输入已有 `course_id`，或进入本地演示模式；没有消费 S1 的 `intent_id` 和 S2 的 EvidencePacket。
- `/workspace` 延迟加载后是固定 6 页演示课件的旧讲稿编辑器，与本次快速排序需求无关。
- 点击“AI 生成脚本”，只为当前预置页面生成以下通用文本：

> 这一页我们先抓住“第1页内容”这个主题。讲解时可以先说明概念，再结合课堂中的典型场景或例子帮助学生建立理解……

没有新建课件、没有新增页面、没有视觉布局、没有快速排序知识，也没有动画或小游戏。

#### 绕过 UI 的完整生成 API

为了区分“前端没接上”和“后端产物本身不合格”，本轮直接调用 `/api/v1/gen/create`。结果为：

| 项目 | 教师要求 | 实际产物 |
|---|---|---|
| 主题 | 快速排序 | 节点正文不含快速排序 |
| 时长 | 45 分钟 | 3 节点 × 5 分钟 = 15 分钟 |
| 知识点 | 分治、枢轴、分区、复杂度 | 核心概念、关键应用、总结过渡 |
| 互动 | 动画演示、课堂小游戏 | 无 |
| 资料证据 | 应可引用 S2 资料 | 无引用 |
| 视觉 | 可上课、精美高级 | 默认白底黑字 |
| 页数 | 应由时长和教学节奏决定 | 固定 4 页（含封面） |

判断：后端存在“生成任务”与“导出文件”的技术能力，但当前 fallback 大纲和导出模板只能证明管道可运行，不能证明课件生成能力完成。

### 2.4 S4：修改、版本与导出

实际结果：

- S4 要求教师手工输入 `Generation ID`；前序页面没有显示或自动透传此 ID。
- 直接 API 可查到 v1，但 S4 页面显示“版本历史 (0)”。
- 修改表单只有操作类型和目标节点 ID，没有自然语言输入，也没有“修改后的内容”输入。
- 添加 `update_node / node_001` 后提交，页面报“无可用节点”。
- 前端修改地址是 `/api/v1/gen/modify`，Go/Python 契约是 `/api/v1/gen/modify/:gen_id`。
- Go 的 modify 路由又错误绑定到了 `GenerationHandler.Create`。直接提交合法 update_node 后，系统没有产生 v2，反而创建了另一个 generation。
- 点击“开始导出”后 UI 永远停在“排队中”；直接 API 导出则可在约 3 秒内完成。

判断：S4 目前是面向开发者内部模型的结构化调试页，不是教师可使用的“说一句话修改课件”产品。

## 四、关键代码根因

| 根因 | 位置 | 说明 |
|---|---|---|
| 启动入口分裂 | `backend/api/main.go`、`backend/cmd/teacher/main.go` | 前者走配置端口但未注册新 Skill；后者注册新 Skill 但端口硬编码 8082 |
| JWT/CORS 顺序错误 | `backend/api/main.go` | JWT 在 CORS 和 OPTIONS 处理之前，预检和 health 会被 401 |
| 修改路由绑定错误 | `backend/internal/router/teacher.go` | `/gen/modify/:gen_id` 映射到 `genHandler.Create` |
| 前后端修改契约不一致 | `frontend/teacher/src/services/v1/versionApi.js` | 前端调用无路径参数的 `/gen/modify`，并使用 `type`；后端需要路径参数与 `command_type` |
| 响应包装不一致 | `frontend/teacher/src/stores/versionStore.js` | store 直接读取 `versions/job_id`，没有解包 Go 的 `{code,data}` |
| 生成入口仍是旧讲稿工具 | `frontend/teacher/src/pages/S3StudioPage.vue`、Workspace | 页面只加载已有课件或演示课件，没有创建完整生成任务 |
| fallback 固定通用节点 | `ai_engine/gen/outline.py` | 无有效 key_points 时固定使用“核心概念 / 关键应用 / 总结过渡” |
| 导出默认空白模板 | `ai_engine/gen/export_ppt.py` | 找不到模板时 `Presentation()`，且内容页仅灌入 title/body |

## 五、解决方向

### P0-1：先统一“一套可运行系统”

1. 确定唯一 Go 入口和唯一开发端口；删除或明确废弃另一套入口。
2. CORS/OPTIONS 和 `/health` 放到 JWT 之前。
3. 在唯一入口注册 auth、旧课件能力和 S1-S4 全部路由。
4. `.env.example`、README、AGENTS.md、Compose 使用同一端口和同一启动命令。
5. 提供可重复的教师种子账号，禁止测试依赖本地 mock 登录状态。

### P0-2：把 S1-S4 收敛成一个 Workspace 状态机

前端只维护一个 `coursewareDraft`：

```text
conversation_id
intent_id + confirmed_intent
selected_material_ids + evidence_packet
generation_id + task_id
current_version
export_job_id
```

这些 ID 自动透传并可恢复，教师界面不展示“请手工输入 Generation ID / course_id”。刷新页面后应从草稿恢复，而不是回到演示课件。

### P0-3：重新定义“课件生成完成”

最低成品不只是 nodes 或脚本，至少包含：

- 与主题和时长匹配的页数与教学节奏；
- 每页明确标题、核心内容、讲者备注和预计时长；
- 至少 3 种版式，而不是所有页同一标题+正文；
- 图示/流程/表格/互动页等视觉内容；
- S2 证据引用和来源标记；
- 可在页面内预览的真实生成 PPT；
- 导出的 PPTX 与预览一致。

45 分钟课程建议初版 12–18 页，不建议固定页数；应由教学环节预算反推页数。

### P0-4：自然语言修改必须成为 S4 主入口

教师输入示例：

> 把分区过程拆成两页，第二页改成扑克牌动画演示，再加一道让学生预测下一步交换位置的互动题，整体保持活泼但不要幼稚。

系统应先展示“修改计划”，教师确认后执行：

```text
自然语言
  → LLM 解析为结构化命令
  → 校验 node_id / 参数 / 锁定状态
  → 生成 v2
  → 展示 v1-v2 差异
  → 重新导出 v2 PPTX
```

下拉框结构化命令可以保留为高级模式，但不能成为教师主交互。

## 六、下一轮统一验收标准

以下 10 条必须在同一台机器、同一次会话内全部通过，才可宣布主链路完成：

1. 教师从首页 1 次点击进入新建课件。
2. 首轮自然语言能正确提取主题、时长、对象、风格、互动要求；教师可逐字段修改。
3. S2 只显示当前用户/当前草稿素材；无证据时明确提示并要求选择“继续无资料生成”或返回补资料。
4. 点击一次“生成课件”后出现可理解的阶段进度，完成后直接预览新课件。
5. 预览内容必须包含本次主题，页数和总时长合理，不能出现通用占位词。
6. 课件至少包含封面、目标/目录、概念、示例或流程、互动、总结，且有多种版式。
7. 教师用一句自然语言提出跨页内容和样式修改，系统先给出可确认的修改计划。
8. 修改成功产生 v2，版本历史能显示 v1/v2，差异可查看，v1 可回滚。
9. 导出 v2 PPTX 成功，下载按钮可用，文件打开无损坏且与预览一致。
10. 整条流程不出现内部 ID 输入框，不依赖演示数据，不允许 silent mock 回退冒充真实成功。

## 七、开会建议

会议不要逐页讨论所有 bug，先做 4 个必须现场拍板的决定：

1. **唯一启动入口是什么？** 谁负责在今天内统一端口、鉴权、CORS、路由和文档。
2. **什么才算“生成课件完成”？** 现场确认上述最低成品标准，禁止再以“返回 nodes / 导出空白 PPTX”判完成。
3. **黄金演示场景是什么？** 建议固定“45 分钟快速排序 + 动画分区 + 课堂小游戏”，全员用同一个场景测试，便于比较。
4. **谁负责横向集成？** A/B/C/D 各自模块之外必须指定一名集成负责人，持续维护共享状态模型和每日人工回归结果。

建议会议产出：

- 一张黄金路径状态图；
- 一份统一 API 契约；
- 一份 10 条验收清单；
- 每个 P0 的负责人、完成日期和依赖；
- 每天下午一次 15 分钟真机演示，只展示真实页面和真实导出文件，不以单测数量代替产品验收。

## 八、本轮验收边界

- 已覆盖真实浏览器中的 S1 对话、S2 检索/空证据、两条 S3 入口、Workspace 脚本生成、S4 版本/修改/导出，并用 API 补测了 UI 不可达的完整生成、版本、修改和 PPTX 导出。
- 本轮 AI Engine 为 mock，不能评价真实 LLM 在有 key 时的语言质量；但无法透传、路由错误、版本解包、空白模板和 UI 断点与模型无关，均为确定性问题。
- 本轮未重复上传大型视频或调用付费视觉模型；S2 图片/视频的识别质量仍按现有专项文档单独验收。
