## 问题 1（已修复）：讲课时间只说"45"无法识别

### 现象

用户输入"讲课时间45"，AI 追问"预计时长是多少分钟？"。必须说"45分钟"才能被识别。

### 根因

`ai_engine/intent/intent_engine.py` 的 `_extract_duration` 方法：

```python
def _extract_duration(text: str):
    m = re.search(r"(\d{1,3})\s*分钟", text)   # ← 必须带"分钟"才匹配
    if m: return int(m.group(1))
    # ... 其他规则 ...
    return None  # 只说"45" → None → 触发追问
```

正则表达式只匹配"数字+分钟"模式，纯数字（如"45"）没有对应匹配规则。

### 影响范围

- `IntentEngine`（无 LLM 时的 fallback）：受影响
- `LLMIntentEngine`（真实 LLM）：system prompt 未明确要求从上下文推断单位，LLM 可能返回 null

### 修复方案

在 `_extract_duration` 中增加纯数字匹配规则（取对话上下文中最近的数字作为分钟数）：

```python
def _extract_duration(text: str):
    # 优先匹配带单位的
    m = re.search(r"(\d{1,3})\s*分钟", text)
    if m: return int(m.group(1))
    # ... 其他规则 ...
    
    # 新增：纯数字匹配（在"时长"/"时间"/"分钟"附近出现的数字）
    m2 = re.search(r"(?:时长|时间|分钟|预计)(?:\s*)(\d{1,3})", text)
    if m2: return int(m2.group(1))
    
    # 兜底：取第一个出现的数字（准确性较低）
    m3 = re.search(r"\b(\d{1,3})\b", text)
    if m3: return int(m3.group(1))
    
    return None
```

同时在 `LLMIntentEngine.SYSTEM_PROMPT` 中增加约束：
```
duration_minutes 必须从上下文推断。输入如"45"表示45分钟，"计划两小时"表示120分钟。
```

### 涉及文件

- `ai_engine/intent/intent_engine.py`（`_extract_duration` 方法）
- `ai_engine/intent/intent_engine.py`（`LLMIntentEngine.SYSTEM_PROMPT` 常量）

## 问题 2（已修复）：教学风格只支持预选词

### 现象

用户输入"风格是活泼型"，系统无法识别，AI 继续追问风格。

### 根因

`IntentEngine._extract_style` 使用白名单正则：

```python
m2 = re.search(
    r"(讲练结合|案例驱动|项目式|项目制|理论为主|探究式|讨论式|翻转课堂|课堂测验)",
    text
)
```

自定义风格（"活泼型"、"幽默风"等）不在白名单中，直接被忽略。

`LLMIntentEngine` 的 system prompt 也未约束 style 字段为固定枚举。

### 影响范围

- 预定义风格以外的需求完全无法处理
- S1 最终提取的 `style` 字段对 S3/S4 无实际约束力

### 修复方案

**方案 A（快）**：扩展白名单 + 自由文本兜底

```python
def _extract_style(text: str) -> str | None:
    # 白名单
    whitelist = ["讲练结合", "案例驱动", "项目式", "项目制", "理论为主", 
                "探究式", "讨论式", "翻转课堂", "课堂测验", "幽默风", "活泼型"]
    for style in whitelist:
        if style in text:
            return style
    
    # 兜底：提取"风格是XXX"中的XXX
    m = re.search(r"风格(?:是|为|：|:)?(.+?)(?:，|,|。|$)", text)
    if m: return m.group(1).strip()
    
    return None
```

**方案 B（正确）**：修改 `IntentSummary.style` 类型支持自由文本，LLM prompt 允许任意风格描述。

### 涉及文件

- `ai_engine/intent/intent_engine.py`（`_extract_style` 方法）
- `ai_engine/core/schema.py`（`IntentSummary.style` 类型）
- `ai_engine/intent/intent_engine.py`（`LLMIntentEngine.SYSTEM_PROMPT`）

## 问题 3（规则链已修复）：AI 偶尔答非所问

### 现象

用户描述需求时，AI 助手的追问与用户实际意图不相关，或在确认环节给出与用户输入矛盾的摘要。

### 可能原因

1. **对话历史拼接问题**：`IntentUnderstandingService._build_extract_prompt` 只用 `"\n".join(f"{item.role}: {item.content}")` 拼接，缺少轮次边界标记，长对话后期丢失上下文
2. **LLM prompt 约束不足**：system prompt 未明确要求"不要重复用户已说过的内容"
3. **missing_fields 推断错误**：`build_followup_questions` 优先推送 `duration_minutes` 追问，但用户可能已经说过了（只是格式不被识别）

### 诊断方法

```bash
# 用测试用例验证不同输入组合的提取结果
curl -X POST http://localhost:8000/intent/extract \
  -H "Content-Type: application/json" \
  -d '{"session_id":"test","messages":[{"role":"teacher","content":"帮我做一个关于Python的课件，45分钟"}]}'
```

### 涉及文件

- `ai_engine/intent/service.py`（`_build_extract_prompt`、`build_followup_questions`）
- `ai_engine/intent/intent_engine.py`（`LLMIntentEngine.SYSTEM_PROMPT`）
