# 4 人团队分工

按照"数据透传 4 个断裂点 + 跨 Store 编排"的思路拆分，每个成员负责一个断裂点的修复。

## 全员协作标准

1. **先定契约，再写代码。**
   - localStorage key 命名、透传数据格式、API 扩展字段在开发前统一冻结（见 `001-当前状态与痛点.md`）。

2. **共享文件最少化。**
   - 原则上只允许少数公共文件被多人同时触碰：
     - `src/stores/generationStore.js`（仅成员 C 加字段，其他人只读）
     - `src/services/v1/generationApi.js`（仅成员 B 扩展，其他人只读）
     - `src/pages/WorkspacePage.vue`（仅成员 D 修改，其他人只读）

3. **只改边界，不改核心。**
   - 每个成员只负责"自己模块的出口"和"下游模块的入口"两端的透传代码。
   - 不修改已有模块的内部业务逻辑。

4. **所有任务可独立验收。**
   - 每个成员完成后，其他人的模块不改也能运行。
   - 验收方式：手动操作流程验证，不依赖自动化测试。

5. **先 localStorage，后 Store 联动。**
   - 第一阶段用 localStorage 做数据透传，保证各页面可独立验证。
   - 第二阶段（可选）升级为 watcher 驱动的 Store-to-Store 联动。

6. **禁止跨区直接改别人模块。**
   - 需要跨模块调整时，在总览里确认影响面再执行。

## 通用交付标准

- 只改指定文件，不引入新依赖
- 刷新页面后数据不丢失
- 空状态、加载态、错误态至少三种状态齐全
- 关键操作有 toast 或状态反馈
- localStorage key 统一使用 `fuww_` 前缀

## 验收方式

每个成员完成后，验收者按以下步骤验证：

1. 打开对应页面，确认自动填充生效
2. 刷新页面，确认数据不丢失
3. 断开 localStorage 模拟空数据，确认优雅降级
4. 清除浏览器控制台无报错

## 成员 A：S1 → S2 意图透传

### 职责

S1 意图数据出口 → S2 资料搜索入口，让 S1 确认的意图自动带到 S2 的知识库搜索。

### 交付物

- `src/pages/S1IntentPage.vue`（加 watcher，监听 parsedIntent → 写 localStorage）
- `src/components/teacher/KnowledgeBasePanel.vue`（加 mounted 读取逻辑，预填搜索框）

### 工作边界

- 不改 S2MaterialWorkspace 的核心逻辑
- 不改 materialStore 的内部实现
- 不修改 S3/S4 的任何代码

### 完成标准

- S1 确认意图后，localStorage 自动写入 `fuww_intent_parsed`
- S2 页面加载时，KnowledgeBasePanel 搜索框自动填入 intent 数据
- 刷新后仍能恢复

## 成员 B：S2 → S3 证据透传

### 职责

S2 证据包出口 → S3 生成上下文入口，让 S2 准备的资料证据自动注入 S3 的 AI 生成请求。

### 交付物

- `src/stores/materialStore.js`（如果需要，在证据生成时写 localStorage）
- `src/services/v1/generationApi.js`（扩展 `generateScript` 以接受 evidence 参数）
- `src/pages/S3StudioPage.vue`（在调用 AI 生成前读取 evidence 并传入）

### 工作边界

- 不改 S2MaterialWorkspace 的核心逻辑
- 不改 generationStore 的内部实现
- 不修改 S1/S4 的任何代码

### 完成标准

- S2 生成证据包后，localStorage 自动写入 `fuww_s2_evidence_packet`
- S3 调用 AI 生成时，自动附加证据包作为上下文
- 后端接到证据参数后能正确返回

## 成员 C：S3 → S4 gen_id 透传

### 职责

S3 生成 ID 出口 → S4 版本管理入口，让 S3 生成的 gen_id 自动带到 S4 版本页。

### 交付物

- `src/stores/generationStore.js`（增加 `lastGenId` 字段 + setter）
- `src/pages/S3StudioPage.vue`（生成完成后写入 lastGenId + localStorage）
- `src/pages/S4VersionPage.vue`（挂载时从 generationStore/localStorage 读取 gen_id）

### 工作边界

- 不改 versionStore 的内部实现
- 不改 S3 生成的核心逻辑
- 不修改 S1/S2 的任何代码

### 完成标准

- S3 生成完成后，generationStore.lastGenId 正确设置
- localStorage 自动写入 `fuww_last_gen_id`
- S4 页面加载时，gen_id 输入框自动填充
- 刷新后仍能恢复

---

## 成员 D：WorkspacePage 跨 Store 编排

### 职责

在 WorkspacePage 中实现所有 4 个 Tab 之间的数据联动，让同一页面内的 Tab 切换也能自动透传。

### 交付物

- `src/pages/WorkspacePage.vue`（添加 watcher 和生命周期钩子）

### 工作边界

- 不改任何 Store 的内部实现
- 不改任何独立路由页面的逻辑
- 不修改 S1/S2/S3/S4 的组件核心

### 完成标准

- intent Tab → material Tab：自动填充搜索框（从 localStorage 读取）
- material Tab → script Tab：自动传递证据（从 localStorage 读取）
- script Tab → version Tab：自动填入 gen_id（从 localStorage 读取）
- 刷新后所有 Tab 间的数据透传仍然有效
