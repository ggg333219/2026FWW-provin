# S1-S4 数据透传整合方案

当前 S1（意图理解）、S2（多模态解析+知识库）、S3（课件生成）、S4（版本管理+导出）四个 Skill 已各自独立开发完成，但**数据流尚未打通**——用户在 S1 确定的意图不会自动带到 S2 的搜索，S2 的知识库证据不会传给 S3 的生成上下文，S3 生成的 gen_id 不会自动注入 S4 的版本管理。

这是一份面向 4 人团队协作的 Store 数据透传整合文档。

## 目标

用最小的代码改动，把 S1→S2→S3→S4 串成一条完整的端到端数据流，让教师能顺畅地：

1. 在 S1 输入教学意图 → 自动带到 S2 资料搜索
2. 在 S2 上传资料、检索知识库、生成证据 → 证据自动注入 S3 生成
3. 在 S3 生成课件大纲 → gen_id 自动注入 S4 版本管理
4. 在 S4 管理版本、修改指令、导出 → 全流程闭环

## 核心原则

1. **最小侵入** — 不改已有模块的核心逻辑，只在边界加透传代码
2. **契约先行** — 透传数据的格式、字段名、存储位置先统一冻结
3. **可独立验收** — 每位成员完成后，其他人的模块不改也能运行
4. **先 localStorage 落地，再 Store 联动** — 保证刷新不丢状态
5. **禁止跨区直接改别人模块** — 需要跨模块调整时，先在总览确认影响面
