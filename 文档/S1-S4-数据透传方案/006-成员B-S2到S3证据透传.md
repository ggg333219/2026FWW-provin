# 成员 B 任务说明

## 职责定位

S2 → S3 证据透传负责人。负责让 S2 知识库检索生成的证据包自动注入 S3 的 AI 生成上下文。

## 目标

- S2 生成证据包后，自动持久化到 localStorage
- S3 调用 AI 生成课件时，自动从 localStorage 读取证据包附加到请求中
- 无证据时正常降级，不报错

## 前置条件

- `materialStore.s3EvidencePayload` getter 已能返回符合后端契约格式的证据包
- `materialStore.latestEvidencePacket` 能获取最新证据包
- `teacherV1Api.coursewares.generateScript()` 需要扩展以接受 evidence 参数
- 后端生成接口需要支持 evidence 上下文（或由前端拼接后传到 AI 引擎）

## 涉及文件

### 文件 1：`src/services/v1/coursewareApi.js`

**改动位置**：`teacherCoursewareApi.generateScript` 方法

**改动内容**：扩展 `generateScript` 方法，增加 `evidence` 可选参数（解构参数）。如果传入了 evidence，则附加到请求 body 中。

```javascript
// 修改前
generateScript: ({ courseId, pageNum, mode = 'llm' }) =>
  requestJson(`/api/v1/teacher/coursewares/${encodeURIComponent(courseId)}/scripts/ai-generate`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ pageNum, mode })
  })

// 修改后
generateScript: ({ courseId, pageNum, mode = 'llm', evidence = null }) => {
  // evidence 为可选参数（S2 证据透传）：有则附加到请求 body，无则行为与原来一致
  const body = { pageNum, mode }
  if (evidence) {
    body.evidence = evidence
  }
  return requestJson(`/api/v1/teacher/coursewares/${encodeURIComponent(courseId)}/scripts/ai-generate`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body)
  })
}
```

**注意事项**：
- evidence 参数为可选，不传时行为与原来完全一致
- 保持向后兼容：已有调用方不需要修改
- 证据包格式与后端约定一致

### 文件 5（同步改动）：`src/services/v1/mockBackend.js`

**改动位置**：`ai-generate` 路由处理 + `buildGeneratedScript` 函数

**改动内容**：Mock 后端读取请求中的 evidence 参数，在生成讲稿时附加证据上下文提示，方便前端验证透传是否生效。

```javascript
// ai-generate 路由处理（修改后）
const evidence = body.evidence
const content = buildGeneratedScript(course.title, page, nodes, evidence)

// buildGeneratedScript（修改后）
function buildGeneratedScript(courseTitle, page, nodes, evidence = null) {
  const parts = [
    `${courseTitle} · 第${page}页 AI 预制讲稿`,
    '',
    '开场：先用1分钟回顾上页关键点，并抛出本页目标。',
    ''
  ]
  // 如果有证据包，在生成讲稿时附加证据上下文提示
  if (evidence && evidence.synthesized_context) {
    parts.push(`📋 证据上下文：${evidence.synthesized_context}`)
    parts.push('')
  }
  if (evidence && Array.isArray(evidence.relevant_chunks) && evidence.relevant_chunks.length > 0) {
    parts.push('参考资料：')
    evidence.relevant_chunks.forEach((chunk, idx) => {
      const snippet = String(chunk.content || '').slice(0, 80)
      parts.push(`  [${idx + 1}] ${snippet}${chunk.content && chunk.content.length > 80 ? '...' : ''}`)
    })
    parts.push('')
  }
  // ... 后续节点内容不变
}
```

## 数据契约

### localStorage Key

| Key | 类型 | 写入时机 | 读取时机 |
|-----|------|---------|---------|
| `fuww_s2_evidence_packet` | JSON string | 证据包生成/绑定时 | S3 调用 AI 生成前 |

### 证据包格式（materialStore.s3EvidencePayload / Mock 后端 handleRagEvidenceRequest 返回格式）

```json
{
  "query": "二次函数图像特征",
  "relevant_chunks": [
    {
      "chunk_id": "chunk_001",
      "content": "二次函数 y=ax²+bx+c 的图像是一条抛物线...",
      "source_type": "pdf",
      "page_ref": 3,
      "seq_index": 0
    }
  ],
  "synthesized_context": "基于检索到的 2 段相关资料，综合整理出与“二次函数图像特征”相关的内容要点，可作为生成环节的参考上下文。",
  "citations": [
    { "chunk_id": "chunk_001", "text_snippet": "二次函数 y=ax²+bx+c 的图像是一条...", "source_ref": "函数与导数基础.pdf" }
  ]
}
```

> 字段说明：
> - `relevant_chunks[].content` / `synthesized_context`：AI 生成讲稿时的参考上下文（Mock 后端会拼进讲稿）
> - `relevant_chunks[].chunk_id` + `citations[].chunk_id`：定位原始资料切片的引用锚点
> - `source_type`：`pdf` / `pptx` / `docx` / `mp4` 等，由 Mock 按素材类型推导
> - 透传时整包原样附加到请求 `body.evidence`，前端不拆分、不转换字段

### 时序说明

1. **S2 阶段（写入）**：用户在 S2MaterialPage 检索知识库 → `materialStore.generateEvidence(query)` 产出证据包 → `addEvidencePacket(query, packet)` 内部调用 `localStorage.setItem('fuww_s2_evidence_packet', JSON.stringify(packet))`。此过程发生在 S2 页面内，S3 完全无感知。
2. **S3 阶段（读取 + 透传）**：用户进入 S3StudioPage 或 Workspace 内嵌 Tab，点击「AI 生成脚本」→ `handleGenerateAIScript` 先 `localStorage.getItem('fuww_s2_evidence_packet')` 并 `JSON.parse` → 非空则作为 `evidence` 传给 `coursewares.generateScript({ courseId, pageNum, evidence })` → 请求 body 变为 `{ pageNum, mode, evidence }`。
3. **Mock 后端（展示生效）**：`ai-generate` 路由从 `body.evidence` 取出证据包 → 传给 `buildGeneratedScript(course.title, page, nodes, evidence)` → 生成讲稿头部追加「📋 证据上下文」和「参考资料」段落。前端刷新讲稿即可肉眼确认透传链路已打通。
4. **降级路径**：localStorage 中无证据包（首次进入 / 已清除）→ `evidence` 为 `null` → `generateScript` 不附加 `evidence` 字段 → Mock 生成普通讲稿（无证据段落），请求与逻辑均不报错。

### 真实链路修复点（本次验收前修复的断点）

验收走的是**真实后端链路**（非 Mock）。过程中修复了两个断点，使 S2→S3 证据透传在真实环境可用：

| 断点 | 根因 | 修复文件 |
|------|------|---------|
| RAG 检索为空 | `.env` 的 `AI_API_KEY=sk-your-key-here` 占位符 → embedding 回退全零向量 → 混合分数上限 0.3 < 阈值 0.6 → 全部滤掉；且向量侧空时 BM25 不执行 | `ai_engine/rag/retrieve.py`（embedding 不可用时退化纯 BM25） |

### 已知限制

- AI 引擎向量库为进程内存（`InMemoryVectorStore`），**重启后需重新点「索引知识库」**恢复数据；因 `texts` 兜底，重新索引即可灌回真实课件切片。
- `.env` 的 `AI_API_KEY` 仍为占位符，真实 LLM 调用会走 fallback；证据注入在 fallback 讲稿中同样生效（已由步骤 5 验证）。
