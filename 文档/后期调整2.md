AI智能课件生成系统 PRD
1 文档概述
1.1 产品背景与定位
本系统是一套面向教师的 AI 智能课件生成工具。教师通过自然语言（文字或语音）阐述教学思路，并上传参考资料，系统借助大语言模型与检索增强生成（RAG）技术，自动完成教学意图理解、知识融合、多模态课件生成，并支持教师迭代修改后导出标准格式课件。
产品目标：让教师从"逐页制作 PPT、手写教案"的重复性劳动中解放出来，在数分钟内获得结构完整、内容丰富、配套教案齐全的课件初稿，再通过对话式迭代快速定稿。
1.2 目标用户
- 主要用户：高校 / K12 教师，需要快速备课、制作课件与教案。
- 使用场景：新开课备课、已有课程改版、公开课 / 汇报课课件制作、配套教案撰写。
1.3 读者与用途
本文档供开发团队、产品评审方与测试同学使用：前者据此排期与实现，后者据此验收。文档同时对照了当前已发现的现状问题与企业原始要求，标注了缺失项与修复优先级。
2 整体业务流程
系统按四阶段串联：教师输入需求 → AI 理解并融合知识 → 生成多模态课件初稿 → 预览迭代与导出。本地知识库贯穿知识融合阶段，大模型贯穿对话、理解与生成全过程。

3 功能需求详述
3.1 S1 多模态交互式需求输入界面
3.1.1 输入方式
- 提供语音输入和文字输入两种方式，允许教师阐述教学思路。
- 语音输入需实现完整的"录音 → 语音转写 → 送入对话引擎"链路，当前版本语音对话未实现，需补齐。
3.1.2 智能对话能力
- 系统能主动发起提问以澄清模糊需求，包括教学目标、知识要点、课时时长、产出风格等。
- 支持多轮对话，并能在对话结束时总结确认最终需求。
- 意图解析引擎需稳定可用——当前存在"一会可以一会不可以"的调用失败问题，需修复至稳定。
3.1.3 参考资料上传
- 支持上传 PDF、Word、PPT、图片、视频等多种格式参考资料。
- 参考资料与教师输入的意图需建立对应关系：教师可指定"参照这个 PDF 里某个知识点的内容"，或"参照这个 PDF 的内容格式 / 排版风格"。
- 智能体需能根据教师要求（如仿照 PDF 中内容格式）从中提取关键信息（如知识结构、案例、排版风格），并融入课件生成过程。
3.2 S2 教学意图理解与知识融合模块
3.2.1 教学要素结构化提取
- 利用大模型理解教师输入的自然语言描述和对话历史，结构化提取教学要素，包括知识点清单、逻辑顺序、重点难点等。
3.2.2 参考资料内容解析
- 对上传的参考资料进行内容解析：文档类做文本提取，视频类做关键帧分析或摘要生成，提取可用的信息片段。
- 多模态处理能力需演示至少两种不同格式（如 PDF 和视频）的信息提取与利用能力。
3.2.3 本地知识库与 RAG
- 用大模型检索增强技术（RAG）实现文本的处理、向量化、检索。
- 知识库资料格式不限；若包含多媒体资料，需说明处理方案。
- 当前问题：知识库为单次灌入，重启后需重新灌入。需改为持久化存储，重启不丢失。
3.2.4 形成课件生成指令集
- 将教师意图、参考资料信息、本地知识库信息三者有效融合，形成详细的课件生成指令集，作为下游生成引擎的输入。
什么是"指令集"：它不是简单的字段传递，而是 S2 输出给 S3 的一份结构化"任务说明书"——把教师意图、参考资料提取结果、知识库召回内容三者融合后，整理成生成引擎可直接消费的完整输入。在代码中应体现为一个独立的数据结构（而非临时拼接的 prompt 字符串），供大纲生成、内容生成、教案生成、互动内容生成全链路复用。

3.2.5 证据包筛选
- 当前问题：S2 自行上传资料生成的证据包不能筛选；绑定后跳转到 S3 才可筛选，但只能在前 10 条中选择。
- 要求：证据包在 S2 阶段即可筛选；筛选结果应覆盖全部条目，而非仅前 10 条。
3.3 S3 多模态课件生成引擎
3.3.1 PPT 生成
- 根据指令集，自动生成包含封面、目录、内容页、总结页的完整 PPT 课件。
- 内容页应图文并茂，逻辑层次清晰。
- 当前问题：
1. 大纲生成 AI 请求超时，走了兜底逻辑——需修复超时或优化兜底质量。
2. 大纲编辑后，新版本不支持手动修改大纲——需恢复并支持手动编辑大纲。
3. 大纲的"内容概述"部分被直接打到 PPT 页面上——需从 PPT 中移除该部分。
4. "一页一页生成"未真正实现，只走了样式——需实现真正的逐页生成。
5. "内容生成"与"全流程生成"区分不清——需明确两者定义与入口。
6. PPT 样式应仅保留颜色主题选择，其余样式选项不成立。
7. 草稿未按项目隔离：新建课件时会跳转到之前的缓存——需按项目 / 课件隔离草稿与缓存。
3.3.2 Word 教案生成
- 生成与 PPT 配套的详细教案，包含：教学目标、教学过程、教学方法、课堂活动设计、课后作业。
- 当前缺失：教学方法、课堂活动设计、课后作业这三项目前没有，需补齐。
- 上述新增三部分在 Word 中需用大字号明确标出，使内容显眼易读。
- 当前问题：Word 标准教案导出格式符合企业要求，但实际一直卡在"导出中"状态，无法导出——需修复导出链路。
3.3.3 内容生成多样性
- 应能根据教师要求生成知识点相关的动画创意、互动小游戏等，至少支持一种。
- 生成课件初稿时，除 PPT 与 Word 教案外，应按教师要求融入知识点动画创意、互动小游戏等多模态内容。
- 当前现状：html5 互动课件形态为"知识翻卡"；蓝色框的 html5 预览是早期 mock，需删除。
3.4 S4 迭代优化与导出功能
3.4.1 课件预览与修改
- 提供课件预览界面，教师可提出修改意见，如"调整顺序""简化某页""增加一个案例"。
- 智能体需能理解修改意见，并对课件进行调整再生。
3.4.2 导出
- 支持将最终满意的课件以标准格式（.pptx、.docx）下载。
- 动画或小游戏可以以 html5 网页、gif、mp4 等格式导出，或集成到 PPT 中。

5 验收标准
1. 教师可通过文字与语音两种方式输入教学思路，并完成至少一轮多轮对话澄清。
2. 系统能输出包含封面、目录、内容页、总结页的 PPT，内容页图文并茂。
3. 系统能输出配套 Word 教案，包含教学目标、教学过程、教学方法、课堂活动设计、课后作业，且后三项以大字号标出。
4. 至少生成一种互动内容（知识点动画或互动小游戏），可导出为 html5 / gif / mp4，或集成到 PPT。
5. 教师可提出修改意见（如调整顺序、简化某页、增加案例），系统能理解并重新生成对应部分。
6. 最终产物可成功导出为 .pptx 与 .docx 文件。
7. 本地知识库重启后数据不丢失；意图解析服务调用稳定。
