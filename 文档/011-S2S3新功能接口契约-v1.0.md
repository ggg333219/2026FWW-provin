## 一、通用规范

### 1.1 统一响应格式
```json
{
  "ok": true,
  "data": {},
  "error": ""
}
```
- 成功：`ok=true`，`data` 放业务数据，`error` 为空
- 失败：`ok=false`，`error` 放错误描述，HTTP 状态码对应错误类型

### 1.2 错误码规范
| HTTP 状态码 | 含义 | 场景 |
|------------|------|------|
| 200 | 成功 | 正常返回 |
| 400 | 参数错误 | 必填字段缺失、格式不对 |
| 401 | 未授权 | 登录态失效 |
| 404 | 资源不存在 | 项目/版本/页面找不到 |
| 500 | 服务器错误 | AI引擎/数据库异常 |
| 502 | 上游错误 | AI引擎调用失败 |

### 1.3 命名规范
- 路径：全部小写，用 `-` 分隔，如 `/page-bindings`
- JSON 字段：全部小写下划线，如 `page_id` / `evidence_refs`
- 字段只增不删，废弃字段标记 `deprecated` 保留一个迭代周期

## 三、新增接口清单（三个模块需要做的）

---

### 模块1：页面级资料绑定（负责人：同学A）

> 核心目标：资料按页面绑定，局部修改带证据

#### 接口1：保存页面绑定
```
PUT /api/v1/coursewares/:project_id/page-bindings
```

**请求体**：
```json
{
  "page_bindings": {
    "page_001": {
      "evidence_refs": ["chunk_001", "chunk_002"],
      "auto_bound": false,
      "bound_by": "user:teacher_demo"
    },
    "page_002": {
      "evidence_refs": ["chunk_003"],
      "auto_bound": true,
      "bound_by": "system:intent_keyword"
    }
  }
}
```

**响应**：
```json
{
  "ok": true,
  "data": {
    "updated_pages": ["page_001", "page_002"]
  },
  "error": ""
}
```

---

#### 接口2：获取页面绑定
```
GET /api/v1/coursewares/:project_id/page-bindings
```

**响应**：
```json
{
  "ok": true,
  "data": {
    "page_bindings": {
      "page_001": {
        "page_id": "page_001",
        "evidence_refs": ["chunk_001", "chunk_002"],
        "auto_bound": false,
        "bound_by": "user:teacher_demo",
        "bound_at": "2026-09-20T14:00:00Z"
      }
    }
  },
  "error": ""
}
```

---

#### 接口3：修改生成时传证据引用（现有接口加字段）
```
POST /api/v1/gen/modify
```

**现有请求体新增字段**：
```json
{
  "gen_id": "gen_123",
  "page_id": "page_003",
  "user_instruction": "把第三页案例改成生活中的例子",
  "evidence_refs": ["chunk_005", "chunk_006"]
}
```

**说明**：
- `page_id`：要修改的页面ID（已有）
- `evidence_refs`：新增，该页面绑定的证据chunk列表，AI生成时只从这些chunk里取上下文
- 不传 `evidence_refs` 时保持现有行为（全库检索），向后兼容

#### 接口3：回滚分叉（现有接口改语义）
```
POST /api/v1/coursewares/:project_id/rollback
```

**请求体**：
```json
{
  "target_version_id": "ver_123"
}
```

**语义变更**：
- ❌ 旧语义：把项目指针移到该版本，覆盖当前草稿
- ✅ 新语义：克隆该版本为一个新的可编辑草稿，当前版本历史保留

**响应**：
```json
{
  "ok": true,
  "data": {
    "new_draft_version_no": 4,
    "base_version_no": 3
  },
  "error": ""
}
```

### 模块3：互动+导出增强（负责人：同学C）

> 核心目标：互动接入S3工作台，导出带版本号

#### 接口1：导出接口带版本号（现有接口加字段）
```
POST /api/v1/exp/:gen_id
```

**现有响应新增字段**：
```json
{
  "ok": true,
  "data": {
    "job_id": "job_123",
    "filename": "TCP三次握手课件_v3.pptx",
    "courseware_title": "TCP三次握手课件",
    "version_no": 3,
    "status": "pending"
  },
  "error": ""
}
```

**说明**：
- `filename`：文件名自动带版本号，格式 `{课件名}_v{版本号}.{扩展名}`
- `courseware_title`：课件标题
- `version_no`：当前版本号

#### 接口2：生成互动后自动绑定到页面（现有接口组合）

## 四、数据模型对齐

### 4.1 PageEvidenceBinding（页面证据绑定）
```yaml
page_id: str               # 页面ID，对应大纲节点ID
evidence_refs: list[str]   # 绑定的chunk_id列表
auto_bound: bool          # true=系统自动绑定，false=教师手动
bound_by: str             # "system:intent_keyword" | "user:<teacher_id>"
bound_at: datetime        # 绑定时间
```

### 4.2 VersionSnapshot（版本快照）
```yaml
version_id: str           # 版本ID
project_id: str           # 所属课件项目
version_no: int           # 版本号（递增）
change_note: str          # 修改说明
outline: dict             # 大纲快照
content: dict             # 内容快照
page_bindings: dict       # 页面绑定快照
style: dict               # 样式配置快照
created_at: datetime      # 创建时间
created_by: str           # 创建人
```

## 六、验收标准

### 模块1验收
- 上传一份PDF → 解析成chunk → 勾选绑定到第3页
- 修改第3页时，AI生成内容只参考绑定的那几个chunk
- 刷新页面后，绑定关系还在

### 模块2验收
- 生成v1 → 修改后存v2 → 再修改存v3
- 点"基于v1回滚" → 生成新的可编辑草稿（v2/v3还在）
- 编辑后保存 → 生成v4，不会覆盖任何旧版本

### 模块3验收
- 选中一页 → 点"生成互动" → 几秒后预览出可玩的小测验
- 导出PPT → 文件名带版本号，互动内容正常显示
- 导出HTML5 → 互动可以正常操作
