# 推进节奏

建议按“先骨架、后模块、再闭环”的顺序迭代，避免互相等待。

## Stage 1：前置接入与骨架打通

周期：1~2 天

任务：

- 全员统一 API 契约
- 成员 A 搭建 AppShell 和 Router
- 成员 B/C/D 建立各自 Store 骨架

## Stage 2：4 大 Skill 专区独立开发

周期：3~4 天

任务：

- 成员 A 完成 S1 意图对话与锁定逻辑
- 成员 B 完成 S2 拖拽上传与 Chunk 渲染 + RAG 面板
- 成员 C 完成 S3 节点树与 PreviewCanvas
- 成员 D 完成 S4 版本迭代面板与导出

## Stage 3：流程串接与状态流转

周期：2 天

任务：

- 联调 S1 -> S2 -> S3 -> S4 的 Store 数据透传
- 确认 chunk、node、version 等核心对象在路由间可持续

## Stage 4：辅助模块接入与 Demo 润色

周期：1~2 天

任务：

- 接回学情分析面板
- 优化全局 Loading / Empty 状态
- 完成答辩演示所需的页面表现
