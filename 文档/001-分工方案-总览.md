# 分工方案总览

> 供 4 人团队（你 + 3 位队友）使用

## 分工原则

按 **3 层架构** 拆分为 3 个独立任务包，每人负责一层，通过**接口契约**对齐：

```
                    ┌─────────────────────┐
    同学 C ──────►  │    Vue Frontend     │  （教师工作台重构）
                    └──────────┬──────────┘
                               │ HTTP REST (API)
                    ┌──────────▼──────────┐
    同学 A ──────►  │    Go Backend       │  （基础设施 + S1/S4）
                    │  Gin + GORM + Redis │
                    └──────────┬──────────┘
                               │ HTTP REST (内部)
                    ┌──────────▼──────────┐
    同学 B ──────►  │  Python AI Engine   │  （S2/S3/KB）
                    │  FastAPI + LLM + RAG│
                    └─────────────────────┘
```

## 分工明细

| 角色 | 负责层 | 核心模块 | 技能要求 |
|------|--------|---------|---------|
| **同学 A** | Go 后端 | Phase 3 代码清理、God Object 拆分、会话管理(S1)、版本/导出(S4)、接口扩展 | Go + GORM + Redis |
| **同学 B** | Python AI Engine | 目录重组、多模态解析(S2)、课件生成(S3)、RAG 知识库(KB) | Python + FastAPI + LLM + RAG |
| **同学 C** | Vue 前端 | 教师工作台重设计、组件按域分组、API 对接、路由搭建 | Vue 3 + Vite + Element |
| **你自己** | 协调+兜底 | 方案把关、接口对齐、进度追踪、风险处理、文档同步 | — |

## 模块与负责人映射

| 模块 | 核心职责 | 原系统状态 | 复用策略 | 负责人 |
|------|---------|-----------|---------|-------|
| Teacher Workspace | 教师输入需求、上传资料、预览修改、导出下载 | △ 部分存在 | 重构主流程，保留已有组件 | 同学 C |
| Conversation | 多轮对话、澄清追问、需求确认 | ❌ 新增 | 新增 | 同学 A + 同学 B |
| Agent Orchestrator | 任务规划与路由 | ❌ 新增 | 新增（Go 调度 + Python 执行） | 同学 A |
| Tool Layer | 文档解析、视频解析、OCR、知识入库 | △ 部分存在 | 扩展并统一为可调用工具 | 同学 B |
| Generation | PPT/Word/互动内容生成与再生成 | △ 部分存在 | 扩展 Prompt 与输出协议 | 同学 B |
| RAG | 知识库构建、切片向量化、检索与证据融合 | ❌ 新增 | 新增主链路 | 同学 B |
| Version | 生成版本、差异、回滚、最终版锁定 | ❌ 新增 | 新增 | 同学 A |
| API Gateway | 统一鉴权、限流、路由与错误规范 | ✅ 已有 | 直接复用并扩展路由 | 同学 A |
| Data Layer | 数据持久化（含 9 张新表） | ✅ 已有核心表 | 复用现有表 + 新增表 | 同学 A |

## 协作边界

| 维度 | 规则 |
|------|------|
| **不互相阻塞** | 同学 C（前端）可以 mock 数据先行开发，不等待后端接口就绪 |
| **不互相等待** | 同学 A 和 同学 B 各自独立推进，只需接口一致即可 |
| **接口即契约** | 所有跨层通信通过 HTTP REST，数据格式见 `005-接口契约手册.md` |
| **先通后优** | 每个模块先跑通基础流程，再优化细节。不要在一个点上钻太久 |
| **问题上报** | 遇到阻塞性难题（超过 2 小时无进展），立即群里同步，不硬扛 |

## 三期推进节奏

```
第一周（集中冲刺）
  ├── 同学 A: 死代码清理 → God Object 拆分 → 会话+版本模块
  ├── 同学 B: 目录重组 → S2 多模态 → KB RAG 管道
  └── 同学 C: 工作台框架 → 对话视图 → 资料管理视图
  
第二周（功能集成）
  ├── 同学 A: 导出模块 → 接口扩展 → 与 B/C 联调
  ├── 同学 B: S3 课件生成 → AI Engine 重构完成
  └── 同学 C: 预览视图 → 修改命令 → 导出视图
  
第三周（联调验收）
  ├── 端到端联调（A+B+C 一起）
  ├── 修复 + 优化
  └── 答辩材料准备
```

## 重要提醒 ⚠️

1. **先读 005-接口契约手册.md** — 所有人必须先统一接口格式再动手写代码
2. **不重构不用的代码** — 只动需要改的部分，现有功能保持稳定
3. **小步提交** — 每个功能点完成就 commit，方便回退
4. **遇到不确定的 API/接口 → 群里问**，不要猜
